## Filled table templates

Common mandatory properties for all four tables below: target crm_chat, owner Chat, business scope with authenticated nonzero/non-system tenant_id NOT NULL; current physical mapping is own Chat candidate database. Runtime uses own SELECT/INSERT, inbox state UPDATE and Contact mutex UPDATE; operator alone has DDL. No SQL/FK/UoW to CRM, Channels or Identity. Reference IDs are logical API references admitted by current Identity and held CRM/Channels reservations. Audit is the immutable request/event receipt plus owning command terminal proof; no body in generic events/logs. Retain keys and original IDs through backup/recovery; no purge/reset in this slice. Content is PII in bounded inbox JSON, protected like message storage; no credential/transcript in evidence. Every write is a local transaction; requests/aliases are append-only. DDL is services/chat/migrations/chat003-ingress.sql, original001–002 checksums unchanged. Runtime must not migrate itself. Interrupted forward migration resumes only from its matching journal checksum and verified own table structures. Older runner rejects the newer lineage; rollback keeps schema/data, disables candidate traffic and forward-fixes. No down migration or reactivation of old writer after new effects.
