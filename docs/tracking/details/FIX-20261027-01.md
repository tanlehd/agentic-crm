## Root cause and changes

- Frontend uses TanStack Query, not Redux. Unnecessary5s capabilities/Page-option polling added load. CHG05 initially made capabilities/options30s and options lazy; CHG06 below supersedes all Inbox intervals with env-configured5minutes plus socket invalidation.
- Nested Identity/CRM operations had2s deadlines inside Chat's10s composed path. Sanitized traces showed cutoffs near2001ms. Exact composed operations now5s; ordinary proof/dispatch/registry deadlines unchanged. Independent self/peer admission checks run concurrently and both must pass. HTTP/TLS connections are reused with bounded pools; every request still checks current authority/revocation.
- Windows API relay previously spawned docker exec/Node per TCP connection, adding process startup and contention; observed Next socket hang up/500. It now multiplexes raw TCP over one persistent docker exec, with64connection/64KiB frame bounds, backpressure and60s idle timeout. No HTTP parsing, credentials, business retry or effect.
- Message timeline already has ix_message_timeline(tenant_id,conversation_id,received_at,id); EXPLAIN uses it with backward scan. Observed SQL2–14ms did not explain multi-second API latency. Rich history had per-message content/reply queries; bounded batching now needs at most3 queries, preserving tenant/connection/conversation scope and redaction. No index/schema migration required. This is evidence for the measured fixture, not a large-tenant capacity claim.
- Docker/WSL wall time stepped backward while monotonic time and Windows remained stable, invalidating signed admission freshness. Registry elapsed-time budget now uses monotonic time. Only an otherwise verified proof invalidated by a measured local clock step permits one new-nonce registry read within the original2s total budget. Suspect proof is discarded; freshness/signature/nonce/peer/tenant checks remain mandatory. Stable-clock stale proofs and business commands never retry.
