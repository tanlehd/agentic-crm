The reference model uses three logical ledgers and an explicit volatile begin-handler continuation. It is test tooling, never exported to application runtime. Peer/authorization inputs stand in for native Identity/mTLS; snapshots serialize JSON, not MySQL crash recovery. Super-admin and real AI execution rules continue to belong to the unchanged Identity implementation; the model does not claim a full replacement policy engine. External provider effect is a counter, not a network request.

Review caught an important context requirement before completion: principal ID alone cannot evaluate team-scope permissions. Issue/inspection now carry owner/revision/record_version/team/shared-team context; Chat validates the snapshot at claim and Identity consume applies current scopes/seat/text rights. Returned model replies are copied so consumer mutation cannot change durable context. Both points have negative regression scenarios. No public message API change.
