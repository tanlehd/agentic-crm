## Adversarial cases required at later composition

1. Pause each process after prepare, reservation, Identity admission, Chat CAS, child commit and consumer commit, then kill/restart. Resolve the same IDs; no admission expiry, reservation TTL or empty404 may authorize a second effect or release unresolved capacity.
2. Concurrent logout/password reset/team removal/field denial/app rotation with non-send read/write. New admission fails as soon as gate closes. Revoke cannot report completed before every affected terminal proof. Owner outage delays completion; status reveals only minimal information to original requester/operator.
3. Workflow recovery/business races are verified in Workflow acceptance. Chat verifies its authorized command state/version/idempotency boundary and single-writer fencing.
4. Apply capacity confirm revision9 before revision8 and release8 afterward; owner9/allocation9 remains. Close completion and transfer are distinguished in workload history. Config disable/reduced capacity drains reservations without falsifying historical load.
5. Delay control close, then deliver reopen/current snapshot before old pause; cumulative watermarks cancel old work only. In-flight D2 message remains unknown/sent as proved; no cancellation label overwrites provider truth.
6. Deliver automation/note event with a valid-looking body but wrong producer, tenant, run definition, source revision or digest. Reject/quarantine, do not hydrate another owner's data. A valid event with temporarily unavailable source stays pending and visibly delayed.
7. Restore snapshots with old receipts/inbox/active graph runs. Legacy `/threads` keys and graph IDs still resolve; no new child key, workflow starter or provider attempt. Consumer offset gaps replay exact events; no synthetic source history.
