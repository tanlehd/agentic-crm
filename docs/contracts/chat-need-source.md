# Chat need source read

CHG-20261023-22, SRC-109/T06, Codex2026-10-23, C2 Ready compatibility refinement. Implements the existing `chat/read-need` contract for the authenticated Workflow peer. This is a Chat read boundary; Workflow execution/follow-up orchestration is outside the task. No schema, event, public API or DDL change.

The request uses the existing tenant, Workflow service actor, Conversation/session/need IDs and expected assessment version. The actor is an active native service_actor under its current role; delegation_id must equal its service actor ID, as in the existing baseline service execution context. Workflow selects its configured actor before invoking Chat; a caller-supplied permission/Access object is never accepted. The endpoint rejects Human/AI actors and non-Workflow peers.

Chat binds a fresh read command to the current Conversation resource/projection, session and requested need version. Identity loads the service actor and canonical field policies from its own storage and requires Conversation read-all, Contact read-all, Conversation text/contact_id read and all five builtin need fields readable. Missing canonical field-object configuration fails closed. CRM's existing session-contact-read rechecks the exact Contact binding, active record and current Identity admission, returning only its ID/version. These are narrow extensions of existing Identity/CRM compatibility adapters; no new CRM or Workflow business feature is introduced.

Chat reads only its own assessment. If the requested positive assessment version is current, return current=true and the five known fields; otherwise return current=false with empty field values, preserving baseline readNeedForWorkflow behavior. Missing or mismatched session/need selects no assessment and also returns current=false after current authorization; a missing Conversation remains NOT_FOUND. No custom property, transcript, proposal, evidence or pin is returned. Closed historical sessions remain readable under current rights. A changed local resource/projection/assessment before delivery commit rejects the snapshot. The Identity admission/abort/settle barrier prevents a completed revoke from being bypassed; transport timeout never grants permission. Recovery settles the original minimized command proof, not the assessment response.

Candidate implementation and eight native acceptance groups: [evidence](../development/chat-need-source-candidate.md). Main runtime/cutover remains pending.

Compatibility: same `OwnerCommandBinding`/read-need schemas and required payload. Extend only the existing session Contact proof/policy allowlists for this named service read; Human note/session routes retain their restrictions. No startup migration or main listener change. Required native checks: current and stale version, wrong session/tenant/peer/actor, current service/field/Contact denial, source outage, snapshot change, terminal proof recovery and no mutation of need/source rows.
