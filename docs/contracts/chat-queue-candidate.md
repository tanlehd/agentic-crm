# Chat queue and sidebar candidate

CHG-20261022-02 / SRC-109 T05. Scoped Ready for the existing Human workspace queue/sidebar contract in [agent workspace](agent-chat-workspace.md). No new business behavior, schema or main routing activation.

Chat owns query normalization, saved inbox visibility, tags, read cohort, snooze, causal waiting coverage, ordering and counts. Identity admits a tenant-scoped Human query and returns finite Conversation read/update predicates (all, own, current team IDs), permitted read/filter fields and inbox-manager visibility. It never sends roles or an Access object. Sharing an inbox does not grant Conversation or Contact read rights. The parent command stays admitted until final delivery; native Identity barriers can abort it during hydration.

Hydration uses batches of at most 100. Authenticated Chat supplies its own Conversation authority snapshots to Identity for current per-row actions/owner kind. CRM supplies its own Contact snapshots to a CRM-only Identity batch decision; Chat cannot supply Contact authority. CRM returns individually redacted summaries or null, rechecking its local snapshots after the policy call. Channels supplies tenant-scoped metadata and retained referral history in batches, including disabled connections. No remote call occurs while holding a SQL transaction. Contact prefix search uses only authorized, readable display names. Owner outage fails the entire query rather than changing counts or returning fabricated labels.

Chat first captures a local snapshot under its writer epoch, performs batched remote reads, and rechecks the local snapshot before committing delivery. The snapshot includes registry/control revisions, shares, query state, inbox definitions/shares, tags, rollout and read cohort. A concurrent local change fails with STALE_VERSION; this is not a distributed database snapshot. Response bodies, Contact summaries and message text are never stored in the parent command proof. Latest message text is selected only after current field permission.

Counts describe all matching permitted Conversations, before cursor pagination. Closed records have no waiting age. Unavailable coverage makes waiting count null. Lazy read cohorts, all-tag matching, expired snoozes, query filter denial, team membership and creator/shared/manager inbox visibility retain baseline semantics. Sidebar uses the same query evaluator with one captured as-of time.

Cursors expire after five minutes and bind tenant/principal, current finite policy digest, normalized query and inbox version. Legacy Access-based cursor bindings must fail QUERY_CHANGED at cutover; T09 must verify reapply/rollback behavior. This additive internal contract preserves public DTOs. Required native evidence: own/team/all and shared-inbox intersection, field/search denies, exact counts and stable page ordering, malformed/expired/changed cursors, retained read cohort and snooze/waiting behavior, disabled metadata, actual owner outage, stale snapshot and completed native logout, public session/query checks. Queue/sidebar remain unavailable in runtime capabilities until handlers and all prerequisite backfills are mounted and verified.

2026-10-23 schema defect correction: chat-workspace.json still described snooze as null-only and actions as mark_read/tags despite the implemented activity contract returning {until,revision} and snooze/wake. Update that public schema additively to match the existing behavior before generating the private owner wire. No new capability or database change is implied.

Native batch verification exposed the old universal two-second deadline during Contact-prefix composition, after the first queue/sidebar groups passed. The two Chat query operations therefore have a fixed ten-second end-to-end read budget; individual Identity/CRM/Channels RPCs retain two seconds. Both client and server derive this budget from the exact owner/operation, never a caller header or option. Queue permits the existing bounded 8 MiB history response limit for 100 latest-message previews; request bodies remain 256 KiB and sidebar remains 256 KiB. The query observes cancellation before more batches and before terminal commit. This is a scoped read-composition limit, not a global timeout increase or an automatic retry of unknown writes.
