## Inbox continuation

Ready scoped extension for existing inbox/options/share operations. Fresh binding uses chat_inbox_catalog and an optional digest-bound inbox_inputs pin containing exact active principal/team reference targets and predicate field keys. Identity validates those targets in its own tenant transaction, current filter rights and native actor; tenant policy mutation drains the admission before changing membership/team state. Account session logout does not make a share recipient principal invalid; active membership/principal status remains the existing reference criterion.

Private admission-inbox-policy returns only viewer principal/current team IDs, auth revision, can_manage_own, can_manage_all, can_share_own and filter_fields. It cannot authorize Conversation data. Directory options are returned only for the admitted inbox-options operation: up to200teams/500Human principals with existing permission/field criteria, overflow explicit. New Connector catalog-connection-read validates only existence of the tenant-bound immutable connection ID, including disabled historical connections. It supplies no credential or dispatch permission; Inbox predicates may reference an inactive connection just as baseline.

Chat owns creator/shares and evaluates current definition visibility in a local snapshot against this bounded policy: list owned/shared definitions only (manager does not enumerate unshared definitions); get permits manager; share only creator with share+manage; transfer only all-manager. Create/transfer quota50 active per creator, max50shares and exact schema1 predicate are retained. Predicate tag references are Chat-local including archived definitions. Snooze-only predicate obeys own rollout flag. Identity and Connector RPCs finish before SQL. Creator quota locks serialize concurrent creators; no arbitrary SQL predicate or remote UoW. Cursor binds policy/query and invalidates on rights change. Same-key receipt replay reauthorizes and never reapplies sharing or transfer. Shared definition visibility never bypasses current Conversation authorization in future queue composition.

Required evidence adds own/shared/manager distinctions, revoked shares/team membership, ownership transfer, exact active target/filter checks, quota/concurrency, lost ACK, catalog-disabled Channel references and public native session/CSRF. No new DDL. Existing owner and admission shapes remain compatible through optional binding pin and additive private operations. Queue/content authorization remains the next scope.

Implementation refinement: quota serialization uses a tenant-scoped MySQL advisory mutex acquired before starting the local transaction, with a 10-second bound and release in finally/on connection loss. The runtime retains SELECT-only rights on the writer gate; it cannot change its own epoch/mode. Current writer gate is held FOR SHARE throughout the transaction. No network call occurs under the mutex. Completed receipt replay omits old target/filter validation pins after a local receipt hint, then rechecks receipt existence/hash and current creator/manage/share rights in commit; a missing receipt fails closed. New commands still validate all references and fields. This preserves baseline replay after an old share target becomes inactive.
