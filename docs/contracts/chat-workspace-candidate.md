# Chat-owned workspace candidate

CHG-20261022-02 continuation, SRC-109/T05. Ready scoped adaptation of [workspace semantics](agent-chat-workspace.md), [owner protocol](chat-owner-v1.md) and [existing data](../data/agent-chat-workspace.md). No DDL or new business permission.

The first owner handlers cover per-Human read-state/mark-read and snooze/get/wake/deadline. Chat snapshots its Conversation registry/control/shares, prepares a fresh command, obtains current Identity admission, then revalidates the snapshot before local commit. Identity requires chat capability and scoped conversation.read; snooze/wake additionally require update. Markers always bind the admitted Human principal, never a supplied principal. Snooze reason is returned only with current update permission; an admission requesting reason may return an empty allowed_fields set. Reads and public receipt replays also acquire fresh admission. Completed account/policy revocation fences prepared commands via the existing drain.

Preserve rollout-cohort unread baseline, decimal uint64 counters, monotonic markers without record-version bumps, legacy receipt route/body hashes, snooze version CAS and closed rejection. Expired generations materialize before rescheduling; one deadline revision may wake once. Local activity, audit, outbox, receipt and projections commit atomically. Reason text stays in the Chat-owned snooze row/command request; it is excluded from events/audit/evidence. Disabled/backfilling feature overrides block public snooze operations but must not stop deadline draining. No baseline migration-number detection; own tables and feature rows are authoritative under the owning schema startup gate.

Transport additively carries existing public errors INVALID_READ_POSITION422, VALIDATION_FAILED422, VERSION_CONFLICT409, CAPABILITY_UNAVAILABLE409 and WORKSPACE_BACKFILLING503. Public schemas/IDs are unchanged. Normalized versioned owner requests recognize retained receipt hashes using either decimal or quoted If-Match; T09 reverse compatibility must also preserve this equivalence when replaying into baseline after rollback.

Tag attach/detach uses the same record admission with exact fields tags, current conversation.read/update and tags read/write. Chat locks its tag definition and links after the Conversation fence; archived tags may be detached or replayed, never newly attached. Preserve the20-tag limit, composite receipt route, tag-set revision, record version and activity/outbox atomicity. Public BFF mounts these candidate record routes with native session/CSRF. Additive public errors ARCHIVED409 and TAG_QUOTA409 retain baseline behavior. Catalog definition management and collection reads remain separate work.

Required evidence: real Identity/Chat HTTP with restricted SQL, marker cohort/monotonic/concurrent/replay/conflict, tenant/service denial, current policy revoke, snooze future bound/version/closed cases, deadline CAS after restart, disabled-feature draining, tag attach/detach/replay/archived/quota/field-denial, atomic activity/outbox and lost settlement ACK. Queue/catalog/notes/session hydration remain additional T05/T06 work; these record handlers do not complete workspace or D3.
