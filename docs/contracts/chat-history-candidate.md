# Chat history candidate — T05

CHG-20261019-27, SRC-109/T05, C2 compatible technical refinement. Dependency T04 DONE. Human-first candidate only; main mounting/cutover stays T07–T09. No physical schema change or historical migration edit.

Implement existing public message history, message-envelopes v2/v3, outbound-intent status and acquisition-session reads on the Chat owning database. Each delivery prepares a new command, obtains current native Identity admission, compares record/owner/control/shared-team snapshot under Chat locks, reads locally, and settles outside SQL before responding. Aborted/revoked admissions cannot release data. No transcript is persisted in read-command results or test evidence. Archived conversations remain inaccessible; closed conversations remain readable.

Identity requires Human Conversation read with existing own/team/all and seat rules. Timeline text is optional: Identity returns only allowed requested fields, and Chat omits text, reply and attachment together when text is denied. Acquisition source fields remain mandatory and a denied field rejects the read. Intent status contains no text. Service/AI/app callers remain unsupported in this Human candidate.

Two minimized private additions fill concrete compatibility gaps before implementation:

- Identity `admission-cursor-subject`: Chat-only recovery request containing the exact command reference and admission ID; returns only `account_id` for an admitted Human timeline command. It resolves the stored native account in Identity, never accepts a caller-supplied account or sends session verifiers. Terminal/mismatched/foreign admissions are rejected. This value is used only in the existing signed cursor binding.
- Connector `history-platform-read`: Chat-only, tenant plus connection ID; Channels owns the SQL adapter in the baseline deployment group and uses its own restricted credential. Returns connection ID and the existing mock_messenger platform. Historical inactive connections remain readable; absent connections fail NOT_FOUND, unsupported platform fails with the existing public error. No provider credential, Contact creation, send or status mutation.

Transport compatibility defects found during composition: retained operation IDs include `intentId`, so the registered-owner path matcher must accept ASCII uppercase in operation names without allowing arbitrary routes. The existing DOMAIN_ERROR wire union must preserve INVALID_CURSOR/400, FIELD_FORBIDDEN/403 and UNSUPPORTED_MESSAGE_PLATFORM/503 across the hop; only explicitly constructed, schema-validated errors are forwarded, with fixed safe messages and no raw exception data. Neither change widens workload allowlists or success payloads.

The legacy public limit of100 messages can exceed the general256KiB owner reply budget (up to100 rich items with64KiB stored content). Allow a bounded8MiB response only for the three exact registered Chat timeline operations, including schema validation and client receive limits. Request bodies remain256KiB, other owner replies256KiB and D2 limits unchanged. Do not truncate a page or change its cursor because the original transport default was smaller. Maximum-page native validation is required.

Timeline cursors preserve the exact legacy account/tenant/parent/filter binding, HMAC key, microsecond timestamp and ascending received_at/id tuple. All three representations share this legacy binding. The injected retained key is required; do not invent a replacement during cutover. Invalid signature or changed binding returns INVALID_CURSOR; the request must still pass fresh Identity admission. No claim that old cursors included policy revision: the legacy verifier did not, and current policy is rechecked on each read. Future private cursors retain the separate owner-lineage contract.

Native acceptance must exercise public session → BFF → Chat → Identity/Channels HTTP with separate credentials, exact legacy cursor continuation, same timestamp ordering, v3 reply scoping and field denial, tenant/parent/actor negatives, current revoke/drain and ACL races, dependency outage/lost ACK, uint64 acquisition pagination, unknown intent lookup without dispatch, and no leaked admitted commands. Use retained synthetic rows and real owning databases; never main/reset. This is a subset of T05: ingress/send/workspace/session writers and remaining owner composition still require their own acceptance before T05 DONE.
