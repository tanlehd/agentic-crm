# Global connection disable candidate

CHG-20261023-10, SRC-109/T05, Ready. Extends the scoped [Channels status writer](chat-ingress-references.md) and preserves [dispatch in-flight semantics](chat-dispatch-v1.md): disable before Connector local start prevents I/O; disable after start may be too late. No recall/resend/forced cancellation of unknown is claimed.

The trusted Channels operator closes/drains its ingress reference gate, invokes authenticated Connector `transport-disable`, then commits its local disabled status/audit. Connector atomically locks its own connection, closes active transport and saves a permanent barrier receipt. No SQL transaction crosses the owner HTTP call. Outage/lost ACK leaves Channels gate closing; the same barrier retries safely. Both local IDs must be the retained canonical connection ID; missing/ambiguous enrollment fails closed.

Connector dispatch HTTP composes AttemptStore with a connection-state lock in each local begin/start/payload transaction, before locking the attempt. A disable that wins the connection lock prevents a fresh admission/local start. Existing terminal receipt lookup and late result application still work. Already-started attempts are kept; disable does not rewrite pending/sent/unknown to cancelled. Stage checks remain current and cannot grant send authority. Old unfenced sender binaries must be stopped before global activation at T09; adding this candidate does not fence an unmodified external process.

Re-enable requires the matching completed disable barrier. Connector first reopens its status with that receipt; Channels then atomically opens its gate/status. Failures keep ingress closed until retry. A permanently enabled receipt cannot be used to disable again, including after multiple later cycles. Channels checks its own completed enable audit under the same gate lock before closing, preventing an old retry from leaving an orphan closing gate. New shutdown uses a new barrier. Wrong tenant/barrier fails; no credential changes/rebind/public admin API.

Private operations `transport-disable`, `transport-enable`, `transport-status` accept `{connection_id,barrier_id}`, allow only the Connector workload (the owning Channels baseline partition), and return IDs plus `disabled|enabled|absent` state. Absence is only a barrier-receipt result after verifying the connection; it is not permission to send. No tokens, provider payloads, or message text cross this control API.

Storage is additive [Connector barrier schema6](../data/connector-connection-barrier.md). Apply only retained native candidate until T09 compatible deployment. Existing main Connector schema5 and Chat4 remain unchanged during candidate work. Tests: populated forward upgrade/hash preservation, current-state race before local start, started/unknown preservation and late result, duplicate/lost ACK/restart, two disable/enable cycles with delayed old requests, wrong tenant/ID, real Channels proof outage and Connector outage, native owner HTTP composition. T06/T07 mount the operational operator/worker and T09 supplies single-writer evidence.
