# Native public Routing read composition

SRC-109/T06, CHG-20261023-17, Codex2026-10-23, Ready. Implements existing GET `/api/v1/human-routing` and `/mine` from [Human Routing](human-routing.md). No DDL, new metrics, AI execution or main mount.

Routing remains the public aggregate owner. It snapshots only Routing profiles/work/queues/allocation statistics and stores a fresh read command in `routing_owner_command` with operation `view`. Its immutable binding pins mine/admin mode, selected profile/Conversation/session IDs and the30day UTC lower bound. The local raw snapshot is hashed; only this hash and terminal proof are retained, never report bodies. Read journals cannot be handled by configuration or dispatch recovery.

Identity admits the current enrolled Human. Admin requires routing.read-all, Conversation read-all/assign-all and owner/team read fields. Mine requires chat capability and any Conversation read grant; only the caller's profile/allocation is selected. Identity returns bounded current read predicates and allowed owner/team fields, and owns availability/active Human/team directory projections. The exact prepared Routing proof and current admission are required at every private policy read. Current revoke/logout aborts the Routing root, so a pending read cannot disclose after completed revocation.

Chat receives only the Routing command/admission reference, obtains its immutable selection and policy from Identity, reads its own current Conversation resources/shares, and returns the visible Conversation IDs. Mine additionally requires current owner equal to the caller; stale allocations never grant visibility. Admin reply aggregates use the admitted session list and lower bound with the [reply-fact semantics](chat-routing-facts.md). Missing selected report sessions fail; absent/archived work Conversations are omitted. Chat rechecks its source snapshot and current policy before returning. No transcript or Contact bodies.

Channels supplies the existing bounded active connection options under the same admitted admin Routing proof. Identity supplies available flags for exactly the selected profile IDs plus current Human/team options for admin. Mine does not fetch directories, reply aggregates or connection options. All owner HTTP runs outside Routing SQL.

Routing validates source digests/selected IDs, masks work owner/team fields, then rechecks its local snapshot under the capacity gate before committing the read journal. Concurrent local changes return stale-version; unknown dependencies return unavailable, never zero/partial metrics. It settles Identity after terminal commit. Recovery uses the exact immutable root proof, does not close/reopen the capacity gate and cannot abort a config/dispatch command. Reads can finish while the capacity gate is closing if their local snapshot still matches; they create no allocation or configuration effect.

Existing DTOs,500work/5000report-session,500profile,50queue,200skill/team bounds and UTC30day semantics remain. Public cookie/header/query validation is explicit; no query or body is accepted on GET. Public/report runtime mounting remains T07; reroute is separate remaining T06 scope.

Required evidence: native Identity/Chat/Channels/Routing composition and public session; admin/mine parity, historical replies, stale-allocation masking, current role/seat/field/tenant/logout, source/config drift, actual outages and overflow. Root proof must reject operation confusion and preserve committed results under late abort. Retain synthetic fixtures; no reset or main runtime changes.
