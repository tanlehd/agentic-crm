# Routing source and work reconciliation

CHG-20261023-23 compatibility disposition: the original unmounted `routing-active` catalog placeholder is superseded by `routing-sync-snapshot` for active/session discovery. Repository callers use the complete snapshot; only generated contract artifacts retain the old name. Its paged `OwnerBatch` cannot prove a complete active cohort for safe reconciliation, so no duplicate runtime route is required. Keep its generated schema as historical compatibility metadata, label it superseded in the source inventory, and require the existing snapshot evidence for CO-05. This does not remove a running route, change public behavior or claim Routing business acceptance.

Add private `chat/routing-sync-snapshot`, callable only by Routing with the registered native `human_routing_dispatch` service actor. Identity requires current active tenant/actor, Conversation read-all and assign-all, and owner/team/channel field read rights. No client Access or permission projection is accepted. A fresh Chat command binds a tenant routing aggregate, exact bounded filter payload and snapshot digest; Identity admission remains abortable until local delivery commit. Chat recomputes the complete snapshot before committing disclosure. No Conversation text or Contact data is included.

Payload carries at most500 principal IDs,500 connection IDs, the all-channels flag and500known session IDs. Match baseline active discovery (profile owners or eligible unassigned channels) and add explicitly known sessions, including closed sessions. Active discovery and known inputs each retain their500limit; union is bounded1000. Return stable session ID/Conversation ID, connection, opened/closed/status, owner/team/revision and assigned timestamp. Missing known sessions are explicit, never interpreted as closed. The complete reply uses a scoped1MiB response bound; no cursor or partial snapshot can silently release work. The prepared binding stores only the query and snapshot digest, not transcript/body; terminal proof records the digest.

Routing snapshots current profiles/queue versions/known work under its own gate, exits SQL for authenticated Chat read, then locks the same gate and rejects changed local configuration/known-work inputs. It reconciles only own Routing tables. Unknown/missing Chat sessions fail closed. Active/pending/snoozed sessions still count; only closed source evidence completes work. Capacity reservations are never released by a snapshot, timeout or missing row. Sessions with an outstanding reservation are left for terminal-proof reconciliation. A monotonic allocation head rejects older owner revisions and cannot revive a closed session. An initial/source-reconciled head has null reservation_id; same/newer actual ownership confirmations remain the existing saga's responsibility.

Reconciliation preserves queue priority/version, earliest current-owner assignment timestamp, allocation/performance history and stable work ID. Profile owners allocate even above a subsequently reduced capacity as existing work; new dispatch still requires reserve/authority/CAS. Idempotent repeat does not create a second allocation or bump a completed work item. Queue selection remains the first enabled priority/ID match, and disabled queues do not accept new work. HTTP never executes under Routing/Chat SQL locks.

No DDL or main worker mount. Existing columns and nullable head reservation_id already support source reconciliation. Required tests: real Identity/Chat/Routing credentials/HTTP, current service/field denial, source drift/outage, own tenant, known missing fail-closed, reserve/confirm ordering, monotonic closed/transfer handling, no duplicate allocation on retry, queue configuration race and retained fixtures. Public work/facts/dispatch and event/scanner wiring remain separate T06 sub-scopes; this adapter alone does not satisfy D3-03.
