# Native ingress terminal-denial classification

Ready scoped C2 extension, CHG-20261021-03, Codex2026-10-21, SRC-109/T05 IN_PROGRESS; T04 DONE. Completes the processor denial sub-scope of [exchange](chat-exchange-v1.md), extending [referral saga](chat-referral-saga.md). No new tables, migrations, worker/public route or main mount.

A generic HTTP FORBIDDEN/REVOKED/NOT_FOUND is not proof that accepted intake is invalid. Chat may diagnose a failed processing attempt only after loading the exact stored tenant/connection/receipt binding. Three private owner ingress-verdict routes return a schema-validated result with digest of tenant plus input: CRM checks immutable identity/Contact/connection/subject digest and live Contact; Channels checks current mock connection/actor/team; Identity checks active service integration.deliver/all and Chat team under its open policy gate. Each owner uses only its SQL. Reply is valid or denied with a sanitized code; generic workload denial, missing route, timeout, malformed response or unknown database result is never converted to a verdict.

CRM missing/archived/mismatched canonical binding produces CONTACT_BINDING_STALE. Disabled/missing Channels connection/service actor or Identity current business permission/team denial produces REVOKED. Channels valid result provides actor/team for Identity diagnostic. Mapping is immutable; restored configuration does not automatically rearm an already failed receipt. Identity closing policy gate is transient, not a permanent denial. Metadata CAS/stale pins, local closing Contact guard, missing imported projection and SQL faults remain received unless a separate current owner verdict confirms permanent denial.

Diagnostics are triggered only for processing Owner/Exchange errors FORBIDDEN, REVOKED, REFERENCE_INVALID, STALE_VERSION or INVALID_TRANSITION. No diagnostic follows INVALID_REQUEST, workload UNAUTHENTICATED, timeout, cancellation, plain SQL errors or payload conflict (already atomic). Check CRM then Channels then Identity, stopping on an explicit denied verdict. Each verdict digest/shape/code/actor scope must match; unknown aborts diagnosis. Missing optional adapter leaves prior fail-closed behavior.

If an attempt created a Chat command, classification first resolves it through existing recovery. Its proof must be aborted, never committed/unknown, and all holds/referral candidates/admissions successfully finalized. Then Chat-local transaction locks Contact mutex and inbox; exact stored binding plus received state/version CAS prevents a stale denial from overwriting a committed or failed receipt. It atomically sets existing allowed error_code and appends one denied audit (system actor, code/owner/input/verdict digests and optional command ref only). It never creates Message/session/touchpoint/outbox business effects. No new successful admission is required for this constrained internal failure cleanup.

The caller still receives the original denial; failure state is durable even if that reply is lost. Public read and accept replay continue current checks; no failure data is disclosed through revoked rights. After restoration, fresh authorized read/process reports failed without reprocessing. Original received ACK stays received. Concurrent successful processing wins when already committed; concurrent terminal diagnostics audit once. Crash before failure commit rolls it back; retry can diagnose again. No automatic failed-to-received API is added.

Required evidence: native owner verdicts, missing/mismatched/archived binding, inactive connection, current role denial before/after command admission and referral cancellation, restored receipt replay, concurrent success/denial and duplicate diagnosis, wrong tenant/binding, transport/metadata/closing-gate transients, malformed verdict, audit rollback/minimization, no prepared commands/holds/candidates left. Synthetic fixtures retained. Full T05 still requires connection disable compatibility, D2 send, workspace/notes/hydration and capability lineage; T06 remains gated.
