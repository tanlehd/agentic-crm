# Facebook OAuth and Page configuration v1

PLAN-004D / SRC-031 / CHG-20261006-13, 2026-10-06. Ready scoped implementation per user: Admin → Channels → Facebook Page list and Connect Facebook using OAuth now, manual server-side token replacement later; channel/page filtering on unified conversations. No live sandbox is available. Existing independent capture and mock bridge are not relabelled as a working provider delivery path.

## Ownership and scope

Channels module owns OAuth, Page catalog and encrypted credentials in the current monolith, target Connector authority per ADR-017. Independent Connector database/capture is unchanged. No cross-database SQL/FK or second writer to these catalog tables. Later extraction must move this authority and provision capture bindings via versioned API. This task configures Facebook assets, not provider subscription/send or capture→Chat dispatch. UI must say Page credential stored, not messaging active.

## API and OAuth

Session-authenticated GET `/api/v1/admin/channels/facebook/pages` requires integration.read(all) plus configure seat, paginated limit1–100/cursor UUID. Output id/channel_id, channel=messenger, page_id, name, team_id, app_id, credential_status(stored/missing), version, connected_at; no token/ciphertext. readiness flag oauth_configured does not claim provider eligibility. POST `/api/v1/admin/channels/facebook/connect` requires CSRF, integration.configure(all), JSON `{team_id}` active chat/general team; returns200 authorization_url for fixed Facebook origin. Each attempt random256bit state, hashed at rest, bound to account+session hash+tenant+team+app, expires10min. New attempt invalidates pending attempts for same account/session/tenant. Repeated starts are safe; state launch is not a business command receipt.

GET `/api/v1/admin/channels/facebook/callback` validates session and stored one-use state, expiry and live configure permission, consumes attempt before external I/O. New start invalidates older in-flight attempts too; commit rechecks current flag and expiry. No caller tenant/team/redirect accepted. Error/cancellation consumes state and redirects to fixed `/` UI marker; retry starts a new flow. Code exchange and paginated `/me/accounts?fields=id,name,access_token,tasks` use fixed Graph v26.0 origin, TLS, redirect:error, timeout10s and bounded1MiB responses; pagination rebuilds fixed path from bounded opaque cursor, never follows upstream next URL. Max20 pages/2000 assets; partial or malformed response saves nothing. Persist Page tokens only; user token remains in request memory. OAuth App secret/key configured on server. Raw codes/tokens/provider errors never logged or returned to browser. Callback proxy access logs disabled and Referrer-Policy:no-referrer.

Commit rechecks account/tenant permission and active team, locks tenant exclusively to serialize local connect; unique(app_id,page_id) prevents another tenant claiming an existing Page. Entire returned catalog batch atomic. Existing Page connection UUID/team preserved on reconnect; token/name refresh and version increment. New channel_connection provider messenger is disabled: credential discovery is not webhook readiness. Missing/revoked assets are not silently deleted or reassigned. Catalog is cumulative across authorizations, not a current-permission guarantee. No Page sends or subscriptions during OAuth.

Config: FACEBOOK_APP_ID, FACEBOOK_APP_SECRET, FACEBOOK_TOKEN_ENCRYPTION_KEY(64hex), optional FACEBOOK_LOGIN_CONFIG_ID; callback is fixed APP_ORIGIN + API path. AES256GCM with tenant/connection/app/page authenticated context. Key stays outside DB. Manual token CLI takes token through stdin, validates Page via fixed Graph `me` and compares ID before encrypting/update; no plaintext SQL token storage. Local fake Graph only injected in tests, never runtime environment endpoint override. Permissions baseline from Meta Messenger overview snapshot: pages_show_list/pages_messaging/pages_manage_metadata/business_management; app review and login configuration must match the real app. Live OAuth remains NOT_RUN until app credentials/redirect set.

## Schema19 and conversation compatibility

Add immutable migration19; migrations1–18 unchanged. Extend channel_connection provider constraint to mock_messenger|messenger; unique tenant/id/provider. New facebook_page tenant/connection PK+FK, unique(app_id,page_id), name, encrypted token nullable, version>=1, timestamps. New facebook_oauth_attempt has state_hash PK, tenant/account/session_hash/team/app, expires_at, consumed_at, is_current; no code/token. Expired attempts pruned on new start for that account/tenant.

Conversation gains persisted channel(default mock_messenger), channel_id generated STORED alias of existing connection_id, composite FK(tenant_id,connection_id,channel) to channel_connection and tenant/channel and tenant/channel_id queue indexes. Existing records backfill without changing IDs; new provider writers must supply actual channel. Legacy dispatch remains mock-only. Additive API output includes channel/channel_id/page_id/channel_name, with page_id from Channels metadata. GET conversations supports channel, channel_id, page_id filters in tenant scope and cursor binding; history remains available when channel disabled. No duplicate authoritative Page IDs on Conversation. Filter options endpoint `/api/v1/conversation-channels` returns only channels from conversations caller can read, with pagination. Reports can group by channel_id and resolve Page ID; report engine is not added.

Local browser verifies Admin/Channel/Facebook list/Connect redirect, cancel/error/config missing, Messenger icons and Page filter. Canonical verify plus release/config checks; live Meta NOT_RUN.
