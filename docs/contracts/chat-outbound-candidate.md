# T05 Chat-owned Human outbound candidate

CHG-20261022-02, SRC-109/T05, Ready scoped implementation. This applies the existing [D2 protocol](human-outbound-runtime.md) and [Chat extraction gate](chat-extraction-runtime.md) to the retained Chat schema. It does not enable main routing or complete T05 by itself.

Chat owns intent/message/job/claim/request/result/coverage/audit/outbox. Reuse the versioned dispatch and exchange wire, stable request/attempt IDs, prepared→claim→begin→deliver phases and conservative unknown handling. Identity current tenant/session/permission and Connector current binding/provider decisions stay authenticated remote authorities. Chat runtime must not read baseline tenant/account/channel tables. Service transport supplies current workload/tenant admission; every local effect also checks Chat writer gate/epoch. Local record/owner/version, text digest, durable grant/claim and receipt binding remain checked at each existing effect boundary. All network calls end before Chat SQL transactions.

Candidate implementation initially coexists with baseline handlers until T06/T09 migration. It imports contracts and workload transport only, with its own mysql2 transactions; it cannot import baseline kernel/UoW/domain code. The worker's lease/CAS writes also honor the writer fence. Scan rows across admitted tenants is scheduling only; each effect is tenant-bound and fenced. A stale worker cannot bypass fencing by saving its phase outside a transaction.

Public Human send keeps existing messages/messages-v2 wire, permission/field checks, idempotency and202/status URL. Identity non-send admission protects the local intent/job commit and settles its terminal command; dispatch issuance/consume separately rechecks the enrolled native session. Replay uses the retained public receipt/intent, reauthorizes current access, never creates a second attempt and never resends unknown. Account identity is resolved only through the admitted Identity subject endpoint; no session verifier enters Chat. Owner changes cancel queued work and fence new claims while terminal result reconciliation remains possible.

Compatibility detail: the existing DOMAIN_ERROR transport envelope additively admits the existing public409 codes CONTACT_BINDING_STALE, IDEMPOTENCY_CONFLICT and OWNER_CONFLICT. No public code/status is renamed. The existing admitted-account subject endpoint additionally permits these two Human send operations; it still requires current admitted proof and returns only account_id.

No new table or migration in this slice: existing Chat schema4 contains the T02/T03 outbound tables and owner command journals. Capability readiness checks own tables/lineage, never fabricated baseline migration numbers. Keep receipt IDs, unknown state and data throughout testing. Existing [job design](../data/chat-outbound-job.md), [claim](../data/chat-dispatch-claim.md), [result](../data/chat-dispatch-result.md) and T02 partition rules remain normative.

Required evidence before acceptance: real retained own-schema intent→authenticated Identity/Connector→claim/result, duplicate/conflicting request, current revoke/owner race, wrong tenant, result replay and unknown→matching-proof sent; writer fence prevents commit/phase updates; workspace coverage and outbox/audit are atomic. Current candidate tests do not constitute T07 packaging or T09 main cutover. Main D2 compatibility repair is separate operational evidence in artifacts/chat-extraction/continuation-20261022.
