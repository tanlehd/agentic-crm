## Boundary

Keep metadata canonical in CRM, permissions canonical in Identity and business authority in each owning module. Current platform API/worker remains one deploy group until extraction evidence. Independent units available now: Reporting and Connector API/worker. Priority Reporting → Connector/Chat → Workflow/AI; Marketing remains separate backlog, not a prerequisite for Chat. Service descriptors describe responsibility boundaries; they do not require immediate creation of every container/schema. No domain/data ownership change, new database table, new business API, broker or live provider action in R1.

Reporting: activate the existing verified image on local port3004 using the current runtime credentials and admission key. Stop only the manager-owned host Reporting, preserve API/BFF URL and Identity grants, start container, verify current native read/query before and after. Capture a sanitized baseline and restore the host process if rollout fails. No automatic migration; preserve own schema7, definitions and receipts. Rollback is explicit container stop→old host start. Operator files remain ignored; no secrets in evidence. No production rollout.

Connector: preserve signed-capture/mock-ingress separation and existing schema2. Add worker health HTTP on default127.0.0.1:3011, configurable CONNECTOR_WORKER_HOST/PORT; Compose binds0.0.0.0 inside its network and does not publish that port in the base file. GET /connector/v1/health/live returns200 while running/draining; GET /connector/v1/health/ready returns200 only after a successful schema-check+worker cycle within45s and not draining/failed. Booting, stale, failed or draining returns503. GET only, other routes404, non-GET405, JSON no-store, status/role only, no counts/tenant IDs/content/token/upstream error text. Health handler does no SQL; each loop checks own schema before claiming. Remote HTTP outage follows existing durable retry and does not falsely label local processing stopped; health confirms ability to operate local queue, not successful downstream delivery.

Worker shutdown immediately marks draining, finishes the current tick, closes health server and pool, maximum40s forced failure deadline; Docker stop grace45s. API stop behavior remains15s with20s grace. Non-root images, read-only filesystem, bounded tmpfs/memory/PIDs/logs, init/cap-drop/no-new-privileges and independent API/worker health. Existing local manager now probes worker health instead of calling process presence ready. Host manager shutdown behavior remains a developer-tool limitation; Docker acceptance tests use graceful SIGTERM.
