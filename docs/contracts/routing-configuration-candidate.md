# Routing configuration candidate — T04

CHG-20261019-26, compatible implementation refinement before code. Public candidate retains POST `/api/v1/human-routing/skills`, `/profiles`, `/team-skills`, `/queues`, native session/Origin/CSRF, idempotency key and If-Match (0 for creation). Main routes stay unchanged. Reroute, automatic dispatch/intake, work/report reads and subscriber mounting belong to T06.

Routing owns configuration SQL and the existing capacity gate/command ledger. Native commands bind the exact configuration digest, original Human delegation, tenant, ID and expected version. Identity admits `routing-configuration` after verifying current routing.manage, conversation read/assign, field rights and Identity-owned active Human/chat-seat or chat/general-team references. Identity drains Routing commands as well as Chat during every policy/account revoke. Recovery selects the owner explicitly and validates proofs against it. No remote call occurs inside a SQL transaction. Configuration closes/drains pending capacity, then commits under the same gate lock; a revoke races the Routing abort/commit lock. Outage leaves the gate closed and the immutable command recoverable.

Public retries recheck native current configuration authority before reading the minimal immutable ID/version receipt. Prepared retries retain the original delegation; a fresh session cannot revive it. Aborts reopen only their own gate. Existing private operator configuration commands remain separate and cannot be submitted through public request DTOs. Skills are immutable and tenant unique; profile/team/queue writes retain CAS and limits. Queue connection validation uses a Channels-owned application read port in the current baseline process, outside Routing SQL; it conveys reference existence only, never send authority. Dispatch always revalidates eligibility/current connection at its own boundary. No new table or historical DDL edit.

T04 evidence must include real public HTTP -> native Identity admissions -> Routing-only writer and Chat drain, wrong tenant/permission/revoked session, same-key replay/conflict, stale version, capacity drain/outage, and revocation before commit. Full dispatch and main mounting are explicitly T06/T09.
