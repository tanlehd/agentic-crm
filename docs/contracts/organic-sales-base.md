# Organic Sales base — scoped exact design PLAN-011A

Status: Ready for scoped implementation2026-10-07. CHG-20261007-14 user prioritizes Lead/Deal → organic Conversation conversion → won value per Page before Marketing integration. Ticket, receipts and full PLAN-011 remain separate. Physical baseline monolith via existing application ports, target Sales schema crm_sales. No service extraction implied.

## Lead create and source

POST /leads retains contact_id, qualification?, qualification_session_id(null only for Human); adds conversation_id? and declared_source? (null or referral/website/facebook/phone/other, version1 catalog). Lead creation is Human explicit command, requires lead.create/read and Contact read. A non-null Conversation must be active/readable same tenant, bound to exactly contact_id; channel and attribution read fields must be allowed. Creation never implies consent/qualification. Retry uses existing durable command receipt; same Conversation may yield multiple intentional Leads via different keys.

Lead domain exposes source_origin(manual/conversation/legacy), source_channel, source_page_id, source_ad_id, source_campaign_id, source_connection_id, source_classification(manual/organic/paid/unknown), source_captured_at and declared_source. Names source_* are reserved, never accepted from client, generic PATCH or custom property definitions. Server snapshot derives from authorized Conversation and Channel reference ports: first persisted touchpoint ordered received_at,id, pinned once. A CTM touchpoint, even without ad_id, is paid; no referral with known channel/Page is organic in this local baseline (meaning no ad referral observed, not a guarantee of all marketing influence); otherwise unknown. Manual source has no channel/Page/ad. Never derive campaign from declared source. New inbound does not update old Lead attribution. Legacy records default legacy/unknown until evidence-only backfill designed; do not infer historical Page from mutable config. Chatflow-created new Leads use the same snapshot writer.

PATCH /objects/lead/records/:id accepts fields.qualification and/or declared_source only, current lead.qualify permission + field write ACL + CAS; qualification still only new/qualifying and inactive session, declared source may change after handoff with proper record scope. Read/filter/source fields honor field ACL. lead.qualified event uses pinned source_touchpoint_id. No public source correction endpoint.

## Deal base

Dedicated POST /deals {contact_id,lead_id?,title,amount,currency}; GET /deals and /deals/:id; PATCH /deals/:id {title?,amount?,currency?,stage?}. Stage open/qualified/proposal/won/lost; create always open. Decimal string amount has ≤14 integer and ≤6 fraction digits, nonnegative; currency uppercase three ASCII letters. Won requires positive amount. Open stages can transition to any stage; won/lost terminal, cannot edit monetary data or reopen in this initial scope. Later correction/reopen design cannot rewrite this phase silently. No implied paid amount. Human requires sales capability + deal.create/read/update grants (admin seat includes sales). New records owned by caller. Lead is optional; if provided must be readable, same Contact and not disqualified; no automatic Lead qualification/acceptance. Many Deals per Lead allowed. Origin Lead immutable; source snapshot copied from Lead at creation; direct Deal is manual/unattributed.

Deal domain uses registry version/ownership/audit/receipt, generic mutation cannot bypass dedicated commands. Read/list use authorized record projections and cursor pagination. Won stamps closed_at server UTC, emits deal.won with IDs and version (no money in event); Customer lifecycle is updated through CRM-owned application port inside approved baseline UoW. Contact remains customer from first won; terminal correction out of scope. Contact archive guard must account for Deal references. CRM UI: Lead source read-only, editable declared source, explicit Create Deal; Deal list/detail/create/update/stage; no fake sales activity. All requests CSRF/tenant validated, If-Match update, Idempotency-Key mutation.

## Organic Page report — SRC-052

GET /sales/reports/organic-pages?from=<UTC RFC3339>&to=<UTC RFC3339> requires sales capability, deal.read and report.read. Half-open close-date range, max366 days. Metric won_value, not cash collected, counts each currently won Deal once, grouped source_channel/source_page_id/currency with source_classification=organic. Manual/paid/legacy/unknown excluded explicitly. Visible totals limited to authorized Deals; required source/amount/currency/stage/closed_at read/filter fields must be readable or fail closed. No SUM float; DECIMAL strings/BigInt arithmetic. Each group includes won_deal_count and won_value; drilldown via authorized Deal records, no Conversation permission bypass. No dependency on Marketing API. Known Page ID is sufficient; names optional labels, not group keys.
