# Human Conversation lifecycle candidate

CHG-20261023-11, SRC-109/T05, Ready. Final handler review confirms T04 supplies the close effect, but no owner handler delivers the full public transition response; open/pending are also missing. This is an existing T05 requirement, not a new workflow or reopening feature.

Preserve POST `/api/v1/conversations/:id/transition`: open↔pending and open/pending→closed, required reason/If-Match/idempotency key, no closed→open and no same-state mutation. Current Human Conversation read/update and status-field read/write are required. Read data follows current detail policy, independent CRM Contact summary and Channels metadata; provider execution remains deferred.

Each attempt prepares a fresh parent admission carrying the same projection as detail. It remains admitted through response delivery, including replay. The parent authorizes read/update and hydrates the field-safe response outside SQL. Open/pending changes commit under that parent with record CAS, local activity, registry snapshot and exact legacy receipt. Close reuses the T04 native Routing/Identity close command as a separately admitted stable child, preserving session/contribution/need events, control fences, snooze, queued cancellation and in-flight/unknown. Both admissions use the same Human session; native revoke drains both and an aborted parent cannot return a response even if the close won.

The close command's internal durable request may additionally contain an immutable prepared public response. Its digest covers that response; old T04 private commands remain byte-compatible when absent. Close finalizes current status/version/time and stores the complete public receipt in the same transaction as the effect. A lost ACK/restart never synthesizes a newer response or repeats close. A concurrent parent that observed the old version retries a fresh admission; stored receipt replay precedes business CAS. Same key/body/version returns the stored data; changed payload conflicts. Imported baseline receipt uses the exact old route and hash `{body,version}`.

Before disclosure, the parent rechecks its Chat resource snapshot (or the exact expected revision/control change of its own close), current allowed detail fields and every stored Contact field. Denied stored fields deny the whole response; latest text/attribution/Channel data never silently reappear on replay. CRM/Channels outage fails closed; no foreign SQL, new physical table or main mount. Routing confirmation can remain pending with durable proof; response failure never compensates a committed close.

The composed public transition owner hop uses a bounded 10-second deadline, like the existing composed session/need operations. Native concurrent-parent and post-close logout tests exceeded the generic 2-second budget. Individual dependency hops keep their existing deadlines; timeout still leaves the immutable receipt/proof recoverable. A public close retry also reconciles an existing committed child before fenced receipt delivery; imported baseline receipts have no fabricated child.

Acceptance: native open/pending/close, immutable legacy and new replay/CAS/concurrent keys; closed-session/history/need effects; native Routing confirmation outage/recovery; field/Contact/tenant denial including receipt; logout before apply/during hydration; public session/CSRF/ETag, source outages and preserved queued/in-flight/unknown. Run affected builds and detail/ownership regression before T05 signoff.
