Chat owns the immutable activity index, encrypted sequence cursor, current message hydration and current Conversation authority. Identity admits a Human with chat entitlement and Conversation read, returning only finite field/automation-read decisions. CRM resolves permitted note bodies from its own Activity registry and field policy; Workflow verifies run trigger Conversation/contact/connection binding against the parent Chat proof's exact projection, using only its own workflow_run storage. Neither owner reads Chat SQL or accepts a raw Access object.

One Chat page scans at most2000 activity references, as the baseline does, and returns at most100 visible items. CRM and Workflow may receive up to2000 ordered source IDs but return only the first requested limit (max100) currently visible sources in that order. This is sufficient for the first100 combined visible items and bounds payloads without silently truncating the public page. The request stays below256KiB; note/message replies allow8MiB. Chat captures its own authority/index snapshot, performs owner calls without SQL locks, rechecks the local snapshot before delivery, and hydrates current local message status/content under that final transaction. Source payloads are never persisted in parent command proofs.

Note visibility and body redaction are independently decided by CRM/Identity on every request. Workflow visibility requires current automation.read on the Conversation; returned references must match stored event definition versions. Denied/missing sources are omitted, source outage produces partial/unavailable freshness, and scanning advances across suppressed items. No hidden sequence or total count is exposed. Message metadata outage marks Chat source unavailable rather than inventing provider metadata. Source freshness comes from each owner's pending notification outbox; Chat uses its own observed timestamps and overdue snooze state. Pending notifications can show delayed even when immediate note reconciliation has already installed the reference, until T06 delivery acknowledges that notification.

Activity cursors preserve authenticated encryption, retained key and five-minute expiry, binding tenant/principal/Conversation, current auth revision and finite policy digests. The new finite binding invalidates old raw-Access bindings with QUERY_CHANGED; T09 verifies this explicitly. Before/after remain exclusive; initial page is newest with ascending returned items, and polling advances the encrypted high watermark across hidden references. The composed Chat command deadline follows [owner v1](chat-owner-v1.md); source RPCs retain2s.

Workflow is the sole automation source after Chatflow retirement. Stale active-contract Chatflow wording is corrected to match the already-retired source/schema; this does not reintroduce adapters or automation features.
