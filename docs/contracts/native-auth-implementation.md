# PLAN-007A — Native auth first slice exact gate

Ready2026-10-07, CHG-20261007-03. Physical current `agentic_crm`, target `crm_identity`; no service extraction. SRC-038 implements this scope after PLAN-007A. Existing schema22 source is retained; SRC-034 validation deferred during this change.

## Wire and UX

JSON only, no extra properties, bounded strings; errors use existing AuthErrorResponse. Login key ASCII `[a-z0-9_.@-]{3,128}`, lowercase; password not normalized,15–128 Unicode codepoints and max512 bytes. Argon2id @node-rs/argon2 exact2.2.2,19MiB/t2/p1,32-byte hash, random salt. Four concurrent hashes/process max, overflow503. Offline version1 common-password deny list shipped in source, no external password lookup.

GET /auth/login redirects /login with validated return_to. GET /auth/login-challenge creates10-minute one-use token bound to HttpOnly crm_login cookie; returns data.csrf_token. POST /auth/login accepts login_key,password,csrf_token; requires Origin and crm_login, consumes challenge atomically; success204 with new crm_session. No return URL from POST; UI uses validated original local path. GET /auth/callback returns410. Session/csrf/logout shapes stay compatible; durable MySQL session idle8h/absolute24h, opaque32-byte token, DB stores hash, CSRF HMAC with SESSION_ENCRYPTION_KEY. Every request validates account status/security revision and DB expiry; Redis not auth authority.

POST /auth/password/change accepts current_password,new_password, requires session+Origin+X-CSRF-Token; success204 clears cookie and revokes all sessions. POST /auth/password/reset-complete accepts token,new_password, requires Origin; one-use15min token, version fence; success204, no auto-login. POST /auth/password/reset-request accepts login_key, Origin; first slice has no mail adapter and always returns503 AUTH_RECOVERY_UNAVAILABLE (same for known/unknown), never falsely claims sent email. UI explains operator recovery. Operator issuance via stdin/local protected file, no token in command args/log. No public signup or generic user creation in this slice.

MySQL auth_attempt counts login attempts in15-minute fixed windows:5/key,30/IP; successful login clears key bucket only, IP budget retained. Challenge60/IP/window and reset30/IP/window. IP uses socket peer (no untrusted forwarded header); proxies share budget until trusted proxy policy separately configured. Counter increment is atomic, denied requests committed; no Redis dependency. API errors never include SQL/credential/username. Origin/CSRF before login/password work; unknown account uses equivalent dummy hash. Rate-limit429 retryable; dependencies503 fail closed.
