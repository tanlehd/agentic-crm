The explicit Chat application processor accepts a stored receipt reference. It loads private canonical intake from its own inbox, rechecks current CRM Contact/mapping and Channels connection/service actor, reserves all three references, and obtains current native Identity ingress-process admission. Additionally it pins/reserves the live CRM conversation metadata snapshot before creating or using its own registry subtype. Existing metadata reference operations expand only to pinned service ingress-process commands; old custom-value behavior remains. No transcript enters command proof/request/results. No scheduler, public processing route or automatic worker is enabled.

Local commit holds command, Contact mutex, inbox and thread registry locks; latest nonarchived thread is preferred with active first. It verifies exact provider message identity/direction/time/text/rich content before duplicate success. New event/same message returns the original IDs without version/workspace/event increments. Payload conflict atomically marks only this inbox failed with MESSAGE_PAYLOAD_CONFLICT. Transient dependency, missing imported projections or transaction failure leaves received. Retries and concurrent processors serialize through the Contact mutex and exact inbox state; committed processing replays original result after current admission. Lost terminal ACK recovers the committed command, never recreates Message.

One transaction contains new/updated Chat registry, thread/control head, Message/content, acquisition membership, session/process/progress/opened contribution, workspace/unread/waiting/activity/snooze, audit/outbox/dataset watermarks and processed receipt. New thread owner is null with the current Channels team. Existing owner/team/owner revision are preserved. The actual process head/version is selected from Chat-owned state; missing tenant default initializes the approved inbox_v2 default exactly once, never inferred from baseline migration numbers. Existing threads require imported workspace/activity/control state; no remote backfill inside SQL.

For an assigned existing thread, owner kind comes only from a retained Chat registry event matching current principal and owner revision. Missing/mismatched evidence fails PRECONDITION_REQUIRED instead of guessing Human/AI or reading Identity SQL. Current reference/service denials leave the inbox received in this slice; durable terminal-denial classification is still pending and must not be counted as complete ingress parity.

Tin before active opening receives unresolved_late membership and does not increment workspace/unread. Tin at/before last close stays on the same closed thread with unresolved_late membership, no reopening or new session. Tin after close reopens the same thread, creates next uint64 session sequence and a new progress row, preserving prior session/source/fields. Registry/control events preserve existing cancellation/pause watermarks, including reopening, and retain durable consumer delivery records.
