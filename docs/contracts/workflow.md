# Workflow primitive contract — SRC-019

ADR-027: one Workflow service owns business automation. CHG-20261021-08 removes legacy Chatflow code, routes and data; historical identifiers in evidence are not supported runtime APIs. Current removal scope is documented in the retirement contract.


SRC-066 additive [CMS contract](workflow-cms-m2.md): GET authoring options and definition by ID, POST graph validation, optional after/next_cursor on definitions. Existing graph/version mutation semantics unchanged; schemas and generated OpenAPI updated.

> Microservices target ADR-017 dùng [cross-service rules](service-boundaries.md). APIs/UoW trong tài liệu này là baseline implementation hiện tại; exact remote contracts và sagas cần PLAN-006 trước extraction.
Status: Ready for implementation M2. CHG-20261005-05.

PLAN-024 / ADR-022 bổ sung [target Web/API/Core](../system/workflow-architecture.md), shared metadata và Kafka object changes. Đây là versioned extension tương lai; wire/graph/UoW bên dưới giữ nguyên cho M2. Exact new schemas/auth/control APIs và compatibility thuộc PLAN-024A…E; không tự đổi strict graph enum hoặc public routes từ architecture document.

All routes use session, X-Tenant-Id; mutations require Origin/CSRF and Idempotency-Key. Definition PATCH and publish require If-Match definition version. POST /workflows accepts {key,name,service_actor_id}; starts disabled. POST /workflows/{id}/versions accepts {graph,execution_role_id}; creates immutable draft snapshot with increasing number. POST /workflows/{id}/versions/{version}/publish accepts {}; version path is number; validates graph and references, pins role, sets active version. PATCH /workflows/{id} accepts {enabled:boolean}. GET /workflows and GET /workflows/{id}/versions return bounded collections (limit1..100, default50). GET /workflow-runs/{id} returns sanitized run/steps/waits, no inputs/context. POST /workflow-runs/{id}/cancel accepts {reason:"operator_cancelled"}. Cancel terminal is idempotent; does not reverse committed actions. No arbitrary execute endpoint.

Design/publish/operate require automation.<action>/all and configure seat; read requires automation.read scoped to related Conversation plus current Conversation read. Definition/version listing requires automation.design/all. Service actor must remain active with the pinned role; all action permissions checked live through owning module ports. Definition change does not change existing run actor/version. Error codes sanitized. Mutation receipts and audit share transaction.

Graph exact shape and primitives follow [module](../modules/workflow.md). Keys match [a-z][a-z0-9_]{0,47}; 1..50 nodes. Typed refs only trigger.aggregate_id/contact_id/connection_id and outputs.<dominator>.<allowlisted_field>. Trigger is metadata, not executable node. UUID inputs permit UUID literals or typed refs; wait match must reference matching request_lead_handoff/handoff_id ancestor. Conditions compare scalar values; eq with missing/null is false. Output fields: assign owner_id(nullable UUID),owner_revision; handoff handoff_id,lead_id; wait_event outcome,lead_id(nullable UUID),timed_out; timer woke_at. Outcome max64 safe code. Wait timeout selects on_timeout; condition uses config.on_true/on_false; end has no edge.

Starter persists definition/event selection even when disabled/no match, within durable consumer transaction. Runs unique version/event and definition/event; pins sanitized trigger IDs. Step key run_id:node_key stays stable for initial attempt +5 transient retries (1/5/30/120/600s). Lease60s, token increments on every claim; heartbeat/recovery15s. No network I/O inside primitive transactions. Action ledger writes owning-module effect and sanitized result in one UoW, separate from step completion: crash gap replays result without repeat effect. Stale token/expired lease cannot commit either effect or step.

Wait registration locks run, reads child predicate via owning port, persists subscription and result atomically. Child check verifies parent run and exact ID. Signals merely wake predicate checks; worker also polls persisted waits so early delivery/Redis loss cannot lose a result. Event predicate is checked before timeout under same run lock; timer/event use one terminal transition. Cancel durably records a child cancellation request in the cancellation UoW; worker calls the child port in a separate UoW, retries at most five times at 15s intervals and retains attention on exhaustion, no deletion of Lead/handoff.

CHG-20261021-08 removes the Chatflow child port. API/worker compose the Sales handoff port only; exact handoff/accept predicates and timeout retention follow [Sales contract](sales-handoff.md). Default constructors retain unavailableChildren for isolated tests.
