# Thread identity, need enrichment and follow-up

PLAN-035 / SRC-081 · CHG-20261016-04 · 2026-10-16. Status: Ready for this bounded implementation. Naming updated by PLAN-036/SRC-082: [conversation identity](conversation-identity.md). User authorized docs, AI need assessment and workflow follow-up. This supersedes earlier gates that excluded explicit follow-up opening and real enrichment adapters, not live channel delivery or autonomous Lead creation.

## Identity and compatibility

Conversation is the persistent channel thread; session is a handling episode. Canonical routes use `/api/v1/conversations/:conversation/sessions/:session`, DTOs use `conversation_id`; `session_id` identifies the episode. Deprecated /threads aliases preserve SRC-081 clients. Forward34 renames four physical thread_id columns, with immutable v1 events/graphs/receipts adapted only when consumed. See [cutover and compatibility](conversation-identity.md).

## Need values and enrichment

Each session_need has an independent assessment, not a Contact score. New additive progress action identify_need registers a need found during review of an already closed, enrolled episode. Its created_at is review time; it appends an audit/contribution, never a behavioral milestone or a backdated stage. Existing need/stage commands stay active-only. This lets closed sessions with no earlier need enter assessment without reopening first. For legacy episodes without progress, identify_need creates review-time partial coverage using the current process template; it never claims a historical stage or includes the episode in the full-coverage funnel denominator. Builtins: assessment_status (unassessed/insufficient/assessed), need_clarity (none/ambiguous/clear), intent (research/buy/support/cancel/other), product_interest (bounded text), unresolved_reason (bounded text). Metadata-only standard object conversation_need adds optional typed custom properties through existing property APIs. No tenant-specific DDL, required/indexed/default custom values or generic record CRUD.

Human edits and AI can fill these fields. Human-written keys are pinned; AI never overwrites them. AI proposal remains inspectable with confidence, exact session message IDs, provider/model/config version, timestamp and input fingerprint; confidence is not conversion probability. Human can explicitly release a pin. AI output is strict JSON, typed and bounded, with evidence IDs checked against the selected session. No milestones, consent, Lead, owner or message effects are inferred by the enrichment call. Zero/oversized evidence fails explicitly. No fabricated default clear need.

Native GET/POST assessment and POST enrich bind authenticated account, tenant, thread, session and need. Mutations require If-Match and Idempotency-Key, current Thread read/update and text/contact plus need field rights. Closed session assessment is allowed as a separate revision; historical session fields/milestones remain immutable. AI network I/O runs outside transaction. Prepare captures version, owner revision, definitions and session evidence; commit rechecks all live rights and fingerprints. Replay returns only a minimal receipt after live access checks. AI requests use a server-configured adapter URL/key/model/version, never tenant-controlled URL or log output. Missing configuration returns AI_CONFIGURATION_REQUIRED. Test adapters only exist in tests; real provider acceptance remains separate evidence.

## Workflow and outcomes

New trigger `need.assessed` v2 carries conversation_id (v1 thread_id remains readable), session_id, need_id, assessment_version, contact_id and connection_id, no transcript/values. It enrolls only published enabled graphs for that connection, with durable event selection and pinned graph/role. An assessment saved before close is evaluated again on close. New read_need action binds the same trigger IDs/version and reads current builtin decision fields through live field ACL; outputs current, assessment_status, need_clarity, intent, product_interest and unresolved_reason for typed condition nodes. Version mismatch returns current=false with empty values; recovery still independently rechecks. Generic custom-field workflow bindings remain the separate Object Platform gate. New action recover_need binds trigger IDs/version, team and Human/AI/any preference, min_confidence, cooldown_seconds and max_age_seconds. Existing wait_timer can delay it. New start_chatflow config uses conversation_id; existing thread_id graphs remain readable.

At execution, recheck live service actor permissions/field rights, assessment version and Human pins, closed/latest session, Thread closed, clear buying intent, evidence freshness, unresolved need, cooldown, and exact Sales outcome. Newer sessions/assessment or outcomes return a skipped receipt with a reason. Sales-owned need outcome links bind an authorized Lead/Deal with the same Contact and session context. Unmapped session outcomes are ambiguous and block recovery until explicitly linked; an unrelated Contact Lead does not block. Linking never creates a Lead or changes sales state.

Success atomically opens a new session in the same Thread, with empty classification/progress and an explicit parent need receipt, then routes through existing owner policy/capacity. Source is unknown (no new inbound attribution invented). At most one recovery per original need, across workflow runs/versions. Receipt survives effect/finish crash gap. Old session, manual evidence, acquisition source and AI revisions are unchanged. No agent eligible rolls back opening. Human owner follows in Inbox; AI owner can continue through an explicitly configured start_chatflow action. Recovery itself sends no message; existing channel/owner/AI capabilities still govern delivery.

## Table designs (filled database-table template)

All four tables: business TenantContext; tenant_id CHAR(36) ASCII binary NOT NULL, no default. Physical baseline monolith pending ADR-017 extraction. No cross-owner FK. Runtime DML only, migration role DDL; immutable ledgers append/read only. No secrets/raw transcript. Values may contain personal data: source retention/access applies; no cascading purge, preserve receipts on restore. Forward33 adds empty tables and metadata, no rewrite of old rows. Rollback disables new workflows/API, preserves data, forward fixes only. Persistent Alpha/Beta fixtures, migration repeat and old-row preservation required. Evidence initially NOT_RUN in SRC-081.

| Table / target / writer | Columns and constraints | Queries, rights, concurrency, events |
|---|---|---|
| need_assessment / crm_chat / Chat | PK(tenant_id,need_id); conversation_id,session_id CHAR36 NOT NULL; values_json,pinned_json,proposal_json JSON NOT NULL; version BIGINT>=1; created_at,updated_at DATETIME(6); same-owner composite FK to session_need | Exact tenant/need reads, Thread lock before CAS; field filtered reads/writes; bounded 64KiB values; append revision + minimized need.assessed outbox atomically |
| need_assessment_revision / crm_chat / Chat | PK(tenant_id,need_id,version); values_json,pinned_json,proposal_json JSON NOT NULL; actor_id CHAR36 NOT NULL; recorded_at DATETIME(6) | Immutable source ledger, reverse version LIMIT50, same assessment ACL; provenance includes evidence IDs and hash; append in assessment transaction |
| need_follow_up / crm_chat / Chat | PK(tenant_id,need_id); conversation_id,source_session_id,session_id,run_id CHAR36 NOT NULL; created_at DATETIME(6); UNIQUE(tenant_id,session_id) | Exact-need durable one-attempt success receipt; Thread lock and workflow action ledger; current service rights; new session + assignment + receipt/audit atomic |
| sales_need_outcome / crm_sales / Sales | PK(tenant_id,need_id,record_id); conversation_id,session_id,record_id,actor_id CHAR36 NOT NULL; created_at DATETIME(6); INDEX(tenant_id,session_id,record_id) | Source link ledger; Sales port validates record read/qualify or update, same contact + context and locks Thread then record; Chat receives boolean/ambiguous result via application port; no SQL/FK to Sales from Chat implementation |

All IDs are existing UUID encoding. Logical remote IDs validated by owning ports; unavailable fails closed. Estimated one assessment per need, revisions bounded per page, one recovery per need, few outcomes per need. EXPLAIN on exact keys recorded with integration evidence. Closed episode enrichment does not falsify historical stage/funnel evidence.

## UI and acceptance

Inbox selected need shows values, AI proposal/provenance, Human edits, pin release, enrich action and outcome binding. Loading/error/CAS conflict retains draft. Missing provider is explicit. Object & Properties supports conversation_need custom fields. Workflow CMS exposes need.assessed and recover_need fields with typed refs; no activation by seed.
