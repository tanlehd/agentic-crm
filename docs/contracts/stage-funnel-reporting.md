# Stage funnel reporting — PLAN-050 / SRC-087

2026-10-18 · CHG-20261018-02 · Ready bounded implementation contract. User authorized code after PLAN-049. Acceptance SF-01…08 from [research](../planning/stage-funnel-reporting.md); bounded execution evidence is recorded in [SRC-087](../tracking/details/SRC-087.md). Fixed Sales lifecycle; required stages only. No configurable Sales pipeline/reopen, canonical merge journey, optional steps, automated alerts or connected durable runs.

## Facts and consistency

Sales writes an append-only `sales_stage_event` on every Lead/Deal creation and changed status/stage in the same existing monolith transaction. Actor human/service and correlation are recorded, one atomic from/to event mirrored to outbox `sales.stage_changed` v1. Consecutive ledger sequence is independent of CRM record revision. Existing record lock serializes writes. No-op produces no transition. First mutation on legacy record captures only its actual from/to, coverage partial; never backfills earlier stages. Full coverage requires creation event from null. All human, Chatflow and Workflow handoff/accept paths participate. Raw Lead IDs retained across merge; histories never stitched.

Chat reuses process version/progress + session_stage_event through an owner read port. Initial stage uses progress.created_at and pinned process definition, marked full only when existing progress coverage is full. Stage command time is recorded_at, ordered by revision; milestone evidence never substitutes. Session closed_at stops active final-stage age, without inventing stage exit or sale. Partial enrollment remains partial. Event sequence gaps in Sales or inconsistent from/to chains fail coverage; missing sources return unavailable, not zero.

Snapshot producer uses REPEATABLE READ and server observation timestamp, at most 10000 total subject/event/config rows, payload <=4MiB, reject excess. Owner ports only: Chat/Sales facts and CRM record metadata. No cross-service SQL/UoW. Native access requires complete Conversation/Contact/Lead/Deal read-all plus field read/filter (export additionally export), rechecked current Identity revision. Stage source follows conservative conversion source policy plus stage fields. Reporting receives minimized IDs/stages/timestamps, never names/transcripts/reasons. No persisted business facts in Reporting.

## Definitions and result

Adapter `native_stage_v1`; static versioned catalog with subject/event/stage-definition objects, three models for Conversation/Lead/Deal. Optional definition `stageFunnel:{processVersion,stages,mode}` where processVersion is positive decimal string, stages 2…20 unique stable keys, mode event_window or entry_cohort. Stage models require this configuration, fixed stage dimension and registered metrics; all other models reject it. Selected stages must belong to the selected object/process version, ordering may choose a subset. Filters apply only to subject owner/team/current stage and identity, never remove events before sequence evaluation. Historical ownership attribution not offered. New visualization `{type:'funnel'}` only for configured stage models; table also supported. Movement/duration shown in stage table alongside funnel count/rates; counts/durations never used as funnel geometry.

Live windows 1…365 days through current snapshot; event_window limits every matched entry to [from,to). Entry cohort uses earliest selected first-stage entry in window and follows ordered subsequence through current asOf. R1 horizon config rejected for stage models (pending = not yet completed at current cutoff, not declared lost). Distinct raw subject counted once per prefix; repeat entries also count visits separately. Same timestamps use source sequence. Only full valid history enters conversion denominator; partial/none totals disclosed, no fake zero coverage. Process definitions remain immutable; obsolete versions can still report. Current asOf only, no historical replay promise.

Results preserve standard rows/metrics/CSV and add `stage` metadata: coverage counts, process/version/mode, distinct cohort, ordered steps with reached/previous and initial conversion percentages, not-yet-next counts and authorized subject IDs for drilldown (bounded by source cap). Zero denominators null. Totals for count = distinct first-stage cohort, never sum stages. Entry/exit visit counts are event activity in window, include partial known transitions with explicit coverage label. Completed average duration uses only paired observed visits; current age uses open visit at asOf, stops on Conversation close; terminal Sales ages excluded. Entry before window can pair with exit inside window. No inferred duration for unknown initial entry. No rounded geometry substitutes for exact strings.
