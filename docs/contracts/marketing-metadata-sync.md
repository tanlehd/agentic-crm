# Periodic Marketing metadata sync v1 — PLAN-011E

Status: Ready for scoped backend implementation,2026-10-08. CHG-20261008-11. Design acceptance only; no deployed API/worker claim. [Database v1](marketing-database.md), [tenant admission](marketing-tenant-admission.md), [field mapping](../data/marketing-field-mapping.md), [request schemas](marketing-authority-v1.schema.json), [control-table templates](marketing-sync-tables.md), [implementation sequence](../planning/marketing-backend.md).

## Scope and current authority

Marketing owns an independent NestJS/TypeScript service, API and worker sharing only `crm_marketing`. The existing Channels module remains authority for Page bindings and provider credentials in baseline `agentic_crm`, target `crm_connector`; standalone Connector capture is not that authority yet. Marketing invokes versioned HTTP ports, never reads Channels tables or imports its implementation. Extraction later changes the endpoint owner without changing protocol or copying credential ownership prematurely.

SRC-056 implements the Channels-side prerequisite ports and scoped account credential setup; SRC-051 then implements scheduling/metadata persistence/read events. These are sequential tasks. SRC-055 Insights and PLAN-022/SRC-049 Reporting remain separate. No ad editing, taxonomy, Contact profiling, demographic attribution, Conversions API or report calculation in this scope. OAuth account-picker UI is not required for the first backend release; authenticated setup accepts an explicitly provided read-authorized account credential and validates it before storing. Existing Page OAuth remains unchanged.

The88 selected metadata descriptors (105 total minus17 Insights descriptors) are authoritative. [Metadata request manifest](../data/marketing-metadata-profile.json) expands their provider field names, including `business{id}` and `creative{id}`; it preserves source-line traces in the existing dictionary. No bulk account creative/audience import. Names/usernames and extra Page/Instagram hydration are outside selected fields; reference rows may exist without those attributes. Page↔Instagram link is never inferred from co-occurrence in a Creative.

## Provider contract and validation

- Pin this adapter to Graph `v25.0` from the saved Marketing sources; Messenger remains independent. Pin is documentation-backed, live eligibility NOT_RUN. Fail closed on unsupported version; no silent version fallback.
- Require read authority corresponding to `ads_read` and account access. Broader app access/review depends on own versus client accounts; [authorization source](../references/meta/2026-10-07-marketing/authorization.md.txt). Do not request `ads_management` for a read-only feature or claim app approval from code.
- First connection validates `GET /v25.0/act_{account_id}?fields=id,account_id,currency,timezone_name` and one bounded `/act_{account_id}/ads?fields=id,account_id&limit=1`. Successful actual read is capability evidence; no invented `/me/permissions`/debug endpoint or assumption that Page token grants Marketing access. Persist verified account identity, checked_at and credential revision. A revoked/expired token later pauses this binding until explicit replacement.
- Data transport is fixed `https://graph.facebook.com`, GET only, Bearer credential in header, redirects rejected, timeout10s, response <=1MiB, Ads page size50, max1000 pages per run. Rebuild pagination from `paging.cursors.after` (ASCII opaque <=2048 bytes); never follow/store `paging.next` URL. No caller URL/path/field expression accepted. Oversized or cyclic pagination fails with sanitized code and retains the last committed checkpoint.
- Fetch Account once per run; scan Ads page by page; hydrate each linked Creative, then only admitted Campaign/Ad Set/audience references. `/act_{account}/ads` and typed object-by-ID reads use exact manifest fields. Check every returned object ID and account_id against request; never use JS Number for IDs. Required identity/parent evidence unavailable means defer, not fabricate a parent.
- Provider enum values remain strings. Integers/decimals parse from lexical strings; reject precision overflow and fractional budget values before SQL. UTC timestamps require explicit source offset; currency remains provider string; no budget/spend conversion. Missing/null/unsupported/forbidden distinguish field coverage. Explicit null clears that current field; absent field preserves last-known value and marks it stale/not_returned rather than asserting deletion.
- Complex JSON uses the selected nested paths in the field mapping, depth<=12,1000 array elements per selected structure, <=1MiB stored JSON. Projection drops all unselected keys recursively. No credentials, access tokens, customer/member lists, arbitrary Graph payloads or transcript fields. Unsupported nested shapes are marked unavailable, never stored wholesale. Actual implementation supplies an exhaustive allowlist and fixtures for every retained complex shape before passing SRC-051 acceptance.
- API error body/message and request URLs are never logged. Normalize transport timeout/5xx/429 and known rate-limit codes into retryable errors; credential/permission failure into attention; invalid field/version into capability attention. Optional field failure does not silently remove it and claim complete coverage. Profile revision changes are explicit forward configuration changes.

## Credential and integration authorization

Admin endpoints remain behind native session, CSRF for writes, current tenant membership/configure seat and `integration.configure(all)`; reads require `integration.read(all)`. Deny system tenant. Credential material is write-only, never returned by list/get/error/audit. Tenant selected by native authenticated context, not trusted body.

Channels stores the separate Ad Account token encrypted AES256GCM using a dedicated externally configured key; AAD includes purpose `marketing-account-v1`, tenant, credential UUID, app ID and external account ID. This is distinct from Messenger Page credential/AAD. Rotation increments credential revision; missing key yields unavailable, not blank data. Account A and tenant B never share a stored credential merely because their external account ID matches. Audit includes only credential reference/state/revision and actor, no token/hash of token.

Marketing gets an opaque `credential_ref`, `credential_owner=channels-v1` and the account/app identity. It calls a typed Graph proxy, so decrypted provider tokens stay inside the authority process. Credential revocation immediately denies new proxy reads and admission grants; already granted immutable admission receipts remain historical decisions (below).

Service auth is a distinct private server-to-server credential registry, configured by operator with `connection_id UUID -> tenant_id, consumer, audience, allowed credential UUIDs, SHA256 bearer token hash, active`. Fixed allowlists, no wildcard account/tenant and no browser session forwarding. Random256bit token, constant-time hash compare, never provider token. Two active hashes permitted only during explicit rotation; disabling removes new access. `X-Integration-Id` selects the registration; tenant is derived from it. Reject Cookie/Origin/X-Tenant-Id, mismatched body tenant and unknown keys. TLS required outside loopback. Existing Connector mock ingress secrets must not be reused. Registry startup validation requires a known business tenant manifest; future native service identity migration is separate.

## Channels authority API v1 — SRC-056

All private POST routes use the service auth above, JSON <=64KiB; response JSON/no-store, `{data,meta:{correlation_id}}` or `{error:{code,retryable},meta}`. UUID strings, decimal/revision strings, RFC3339 UTC timestamps; additional properties rejected. No foreign tenant ID in any response. These routes are namespaced `/internal/v1/marketing-authority`.

| Route / action | Exact input | Output and rules |
|---|---|---|
| POST `/graph-read` | `credential_ref`, `operation=account\|ads_page\|campaign\|ad_set\|ad\|creative\|audience`, `external_id` required except account/ads_page, optional `after` only ads_page | Selected object or `{items,next_after}`, `credential_revision`, `api_version`, `fetched_at`, field coverage. Account fixed by credential; external ID is validated and account scope checked in response; never arbitrary URL/query |
| POST `/page-check` | `credential_ref`, `page_id` | `decision=match\|skip\|defer`; match includes binding ref/namespace/revision and checked_at. Namespace derives configured app ID; foreign ownership returns skip without owner identity; missing/revoked/ambiguous returns defer |
| POST `/admit` | `operation_id`, `credential_ref`, `expected_credential_revision`, `page_id`, `expected_page_revision`, `external_ad_id`, `payload_sha256`, `run_id`, `fence`, `fetched_at` | Match creates immutable receipt: receipt_id, scope tenant/account, page_binding_ref/namespace/revision, credential revision, admitted_at, payload digest, policy_version=`page_account_v1`. Same key/body returns same receipt; conflicting digest409; changed authority409 `ADMISSION_STALE`; foreign skip never creates receipt |
| GET `/receipts/:operation_id` | No query/body | Own-authorized receipt or404; recovers lost response after authority commit. No re-evaluation or re-admission disguised as original receipt |

Admin credential routes `/api/v1/admin/channels/marketing/credentials`: POST `{app_id,external_account_id,token,operation_id}` verifies provider reads before commit; PATCH `/:id` `{expected_version,token,operation_id}` replaces after verification; POST `/:id/revoke` `{expected_version,operation_id}`; GET paginated `?limit=1..100&cursor=<UUID>` returns metadata only. Mutation idempotency uses existing durable command receipts; token must never enter generic serialized command payload/audit (digest an HMAC of normalized body using a separate operation key, not plaintext/unsalted token hash). Failed verification stores no credential. Same account+app+tenant uses stable credential identity; reconnect updates revision. Native tenant/admin permission rechecked after remote I/O before committing. No self-service account OAuth UI in this slice.

## Resolve Creative Page and commit admission

`object_story_spec.page_id` is explicit evidence. Saved [Creative reference](../references/meta/2026-10-07-marketing/creative.md.txt) defines `actor_id` as the Creative's Page ID: adapter may accept it only from this typed Creative response and a matching authoritative Page binding. Both present but unequal => defer. For existing-post Creative with actor_id, preserve post IDs and verified Page independently; never parse a Post ID prefix or assume a generic actor is a Page. If neither typed Page field is available, defer with `PAGE_EVIDENCE_MISSING`; additional Post→Page endpoint discovery is a future capability extension, not a guessed route. Instagram-only evidence also defers.

Page admission validity means registered Page→tenant ownership, not Messenger delivery readiness. Existing `channel_connection.status=disabled` after Page setup is not sufficient to reject the Page: that flag controls messaging transport. Add explicit Marketing admission state/version on `facebook_page`, described in table templates. Existing Page bindings bootstrap enabled under their current immutable owner; no ownership transfer API. Explicit Marketing admission revoke disables new grants without altering historical CRM sources or disabling messaging.

Worker performs preliminary page-check before hydrating/persisting related metadata. It builds a minimized canonical bundle and computes SHA256, then calls `/admit` with observed revisions as the final remote step before local persistence. Authority transaction locks credential then Page in fixed order; it checks current state/revisions and writes receipt atomically with its local journal. This grant is the authorization linearization point. A grant before revocation may finish persistence afterward as an already accepted historical observation; a request after revocation is denied. This is explicit, bounded by grant semantics, not a claim of distributed SQL atomicity. Revocation never rewrites prior receipt/Lead/Deal evidence.

Marketing's commit transaction rechecks active binding, schedule fence/lease, exact run, receipt scope/digest and observation age. It persists the accepted bundle plus receipt reference, current projections, link/history, change events, counters and checkpoint atomically. Old worker token cannot commit after takeover. Receipt cannot be reused for another tenant/ad/bundle/run/fence. Recovery after a lost response fetches the same receipt only while that run/fence remains valid; takeover requires fresh authority validation with a new operation ID. Pending request contents are in worker memory; skipped/deferred foreign content is never persisted. A crash before commit may refetch and produce a new digest, requiring a new admission operation.

## Periodic execution and recovery — SRC-051

Freshness bounds: `/admit` rejects fetched_at older than5min or more than30s in the future relative to authority UTC time; Marketing also rejects a bundle older than5min before persistence. Receipt retrieval is historical and does not renew either freshness or a worker lease. Positive revision/fence strings must fit unsigned BIGINT, not merely the lexical request regex. Dates/UUID/IDs receive semantic validation after schema checks. Service registration is operator-provisioned for this initial backend slice; automatic service-identity enrollment during a future account OAuth UI is not implied.

Defaults are implementation configuration, not customer retention policy: metadata full bounded scan every6h; first validated binding schedules immediately; enabled explicit per binding; worker tick15s; lease60s renewed every20s; process one Ad bundle at a time; up to4 account jobs globally and1 per tenant/account/profile. Every scan begins at start and includes all statuses supported by the validated edge; no updated_time-only strategy. Thus budget changes are reconciled even when Meta updated_time is unchanged. Last-known objects absent from an incomplete scan are never deleted.

`marketing_sync_schedule` holds due_at, binding/profile, fence/lease, active run and state. Scheduler claims due rows with `FOR UPDATE SKIP LOCKED`, monotonic fence increment, creates or resumes an incomplete run, then does network work outside transaction. The next due time is scheduled from completion plus6h with deterministic <=10% spread; manual request coalesces with active run. No parallel full scan/incremental writer. Dispatcher is a narrowly scoped cross-tenant queue scan; each claim instantiates one explicit tenant context, all object queries carry it.

Checkpoint v1: `{profile_version, after, last_committed_ad_id, page_digest, scanned_count, completed_pages}`. Page digest helps detect changed provider pagination; if page cannot be replayed consistently, restart scanning from the account beginning under the same run, relying on object-content idempotency. Cursor expiration similarly restarts boundedly (max2 per run). Never store entire pages or URLs. Skip advances progress and increments mismatch count. Defer increments count and leaves no foreign content; next periodic full scan retries it. A run with deferred items exposes `complete_with_gaps` in the API using stored completed status + nonzero unresolved counters; never says all Ads imported.

Retry transport/rate limit uses full jitter over min(15s*2^attempt,15min), honors bounded Retry-After<=1h, at most8 consecutive failures then schedule `attention`. Successful page progress resets consecutive failures. Retry preserves run/checkpoint, releases lease and sets due_at; restart reclaims expired lease with a new fence. Permission revoked/unsupported API field/version => attention immediately; no automatic fallback token, tenant or fields. Credential replacement/manual resume clears attention only after a successful capability check. Pages/Ads limits hit => attention with checkpoint retained; operator can configure a higher reviewed bounded limit, no unbounded loop.

Observation revision changes only when canonical selected payload, field coverage, provider parent IDs or admission binding revision change. fetched_at/last_seen_at alone do not create revisions/events. Current projection's missing fields preserve prior values with stale coverage; each immutable observation still shows precisely what was returned. Compare against latest accepted content under row lock; out-of-order fetched_at cannot replace later accepted state. Shared Campaign/Ad Set are replica context; parent budgets are not tenant spend. Reused parents/config within an admitted bundle must not cause duplicate content/targeting revisions. No write from a foreign Ad may alter a previously admitted shared parent's snapshot.

## Marketing management/read API v1

Private service requests use a separate Marketing audience registration with own permitted tenant; human access goes through native BFF with live integration permission, never a service token in browser. Actor/delegation is validated in BFF. Service tokens are not a general way to bypass field permissions; this API exposes integration metadata only, no CRM outcomes or credential values.

| Route under `/marketing/v1` | Contract |
|---|---|
| POST `/bindings` | `{operation_id,credential_ref,external_account_id,app_id}`; validate authority/account before tenant-local account/binding creation. Stable idempotency,409 differing body, no raw token; initial schedule enabled only after verification |
| POST `/bindings/:id/sync` | `{operation_id}`;202 run_id/queued; active run coalesces, no second writer |
| PATCH `/bindings/:id` | `{operation_id,expected_version,enabled:boolean}`; CAS pause/resume schedule. Pause increments fence, invalidates active lease; preserves all data |
| GET `/bindings` | limit1..100/cursor UUID, metadata/status/last_success/next_due, sanitized counts/errors and version |
| GET `/runs/:id` | Own tenant run/counters/checkpoint progress/error/freshness; no cursor secrets, provider payloads or foreign IDs |
| GET `/ads/:external_ad_id` | Optional own local `account_id` UUID. Exact unique admitted mapping returns hierarchy+Creative refs/revisions/Page evidence/coverage. Missing404, multiple accounts409 `AMBIGUOUS_AD_SOURCE`; never guess account or mutate CRM source |
| GET `/changes` | `after` opaque tenant-bound cursor + `limit`1..100; durable metadata change descriptors up to pinned watermark, no raw creative body by default |
| GET `/snapshots` | `cursor` optional,limit1..100; consistent watermark page of current object references/revisions; subsequent change tail fills updates. Historical backdating unavailable before first observation |

Write operation receipts are tenant+operation scoped; normalized body digest, action/target, response metadata committed atomically. Same operation/body returns original result; changed body409. Cursor signed with tenant/audience/query hash and last sequence, expiry24h; invalid/foreign400 generic. Snapshot consistency uses immutable observation references at pinned event watermark; retain selected revision rows, never paginate mutable rows without pinning. Changes expose event_id, tenant_id, type=`marketing.object.observed.v1`, object kind/external+local identity, account_id, observation_id, revision, observed_at, mapping_version, Page evidence reference and scope descriptors. No total spend or CRM conversion metrics. Delivery is durable pull, at-least-once, consumer dedups event_id; external message broker publisher remains a later transport option.

Retention in this initial backend: no automatic deletion of provider observations, admitted references, receipts or change history; bounded payloads and object scope as above. History grows until an explicit governed retention/backfill/consumer watermark contract is implemented. Operational error messages are enumerated codes; audit field names only. No fabricated production retention/SLA promise. Disconnection disables fetching and future admission, retains historical read permissions subject to current tenant authorization.

MKT-SYNC-02 worker: matching/foreign/unknown/conflicting Pages and typed existing-post actor; no foreign payload/history/event, same parent replicas in A/B, field coverage/null/unknown enum, opaque ID/decimal overflow, all88 metadata descriptors, nested minimization, partial pages, duplicate/cyclic/expired cursor, no delete on absence, rate-limit/backoff/attention, same content no revision, budget change without updated_time, parent-chain mismatch, retry after commit, crash/lease takeover/stale fence, pause/reconnect and indexed bounded dispatcher.

MKT-SYNC-03 consumers: tenant/field ACL, no credential/token, ad lookup ambiguous/unresolved, immutable Session/Lead/Deal values unchanged, snapshot watermark/change tail no gaps, event redelivery, bounded cursors and retention availability. Validate migration preserve v1 rows/checksums and source local DB26 with forward migrations only. Persistent fixture users/tenants retained. Real Meta account smoke is separate LIVE gate and remains NOT_RUN until configured; local fixture success cannot close it.
