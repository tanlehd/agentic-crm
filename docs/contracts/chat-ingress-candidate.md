# Native ingress candidate — T05

Current CHG-20261021-01: [organic processor contract](chat-ingress-processor.md) and [native runbook](../development/chat-ingress-processor.md) extend this earlier accept/read slice. Explicit non-referral processing now creates actual Message/session effects. Referral/touchpoint and full T05 remain pending; accept/read wire is unchanged.

CHG-20261020-02, Codex2026-10-20, IN_PROGRESS. Implements the unchanged [exchange v1](chat-exchange-v1.md) accept/read wire using existing workload transport, with [forward storage](../data/chat-ingress-storage.md) and [reference pins](chat-ingress-references.md). Mock Messenger only; no main activation or provider relabel.

Channels adds private connection-ingress-read (Chat only): active connection, platform, immutable channel_id, team_id, service_actor_id. No caller chooses the integration actor. New optional digest-bound OwnerCommandBinding.ingress_channel pins those3fields, preserving all old command digests when absent. Connection reservation rechecks them against its own current configuration. Identity authorizes service ingress-accept/process/receipt only with that pin, actor delegation_id=principal_id=service_actor_id, active service role granting integration.deliver/all and active Chat/general team. The existing Identity tenant policy barrier/drain prevents admitted commits after completed revoke. Workload admission does not replace business admission.

Every accept, duplicate accept and receipt read uses a fresh Chat command and current Identity admission plus Contact/mapping/connection holds. Owner command request stores only request/event digest and receipt references, not transcript. New commands can safely retry the same immutable exchange request after a prior admission abort; the exchange request/event/source ledgers provide business dedup. No remote call under SQL. A timed-out operation may still commit; retry resolves the original durable receipt. Terminal Chat proof releases holds and settles Identity; missing cleanup ACK leaves recoverable reservations.

Canonical occurred_at rejects impossible calendar dates and normalizes supported timestamps to UTC milliseconds before request/event digest. Exact input message/referral/subject remain unchanged. Max accept96KiB; normalized message64KiB; receipt read16KiB. Source/request keys include connection and tenant; event key also provider_event_id. Alias and accepted inbox commit together. Conflict rolls back everything. Accept always returns the original received ACK/receipt_id, including after processing; ingress-read returns current minimized receipt after fresh binding checks.

Chat ingress_contact_head serializes ingress for a Contact key; it does not own Contact lifecycle. Existing chat_contact_guard checks remain source compatibility only; see [legacy archive](legacy-record-archive.md). No new Contact archive writer/fence protocol is required. Current connection validity remains a Connector responsibility.

Acceptance/receipt implementation and processor lifecycle are separate sub-scopes of T05. No received receipt means a Message exists. No stub processor may mark processed. The actual processor must preserve stable thread IDs, exact message dedup, active/late/closed session boundaries, referral/touchpoint, workspace/activity/process/contribution and durable downstream events in one local transaction. If that composition is not yet verified, received stays received and processor remains unmounted. No T05 DONE claim until full task criteria hold.
