## Native API and authorization

Public routes `/api/v1/reporting/definitions`: GET list, POST create; `/:id` GET and PATCH; `/:id/versions/:version` GET; `/:id/archive` POST (body archived boolean supports restore). Strict JSON envelope, unknown keys rejected. Create `{name,definition}`, update `{name,definition}` is complete draft replacement, archive `{archived}`. Names1..160 trimmed, definitions JSON object<=64KiB, depth<=12, no execution; incomplete/semantically invalid drafts can be saved. Detail/version/command responses always label validation_state=unvalidated and execution_enabled=false; list returns heads only. Public schema/OpenAPI is a dedicated generated contract; native module registered in backend bootstrap. Existing product OpenAPI paths remain compatible.

Native session from opaque cookie; mutations require Origin+CSRF via existing NativeAuthService, application/json and Idempotency-Key UUID. Tenant header is only selection, Identity membership determines access. New reviewed resource `report_definition`: read requires read seat capability; design (create/edit/archive) requires configure. Grants own/all; team sharing deliberately unavailable. Default private owner principal is immutable. A tenant all-scope admin can manage definitions in their own tenant. Read does not grant source-record access and response contains no KPI/source rows. Missing/foreign/non-owned report returns404; missing resource permission403.

PATCH/archive require strong If-Match `"revision"`; absent428, stale409. Create revision1/edit version1; update increments both revision/edit version; archive/restore increments revision only. GET includes latest draft and ETag; historical version is immutable. List uses ascending opaque UUID keyset `after` (validated UUID, never authority), limit1..100; current permissions applied on every page before data returned; no global counts. Request tenant/principal/owner cannot be supplied in body.

BFF talks HTTP only to independent Reporting API (no direct DB access/import). It authenticates native session and resolves Identity grants in a short Identity UoW, releases it before network call, then signs a request-specific assertion. Header assertion HMAC-SHA256 secret from env; payload binds audience=reporting-definition-v1, exact serialized operation digest, tenant/principal/auth revision, own/all read/design scopes, issue time and expiry max5s. Reporting verifies signature/body/scope/expiry before request and again immediately before local commit. Signed admission is the authorization decision point: revocation after issuance can leave an already admitted write within5s; no claim of cross-service linearizable revocation/shared UoW. BFF rechecks live session and auth revision before releasing any result. Lost response/revoked-after-commit can return denied while command committed; same idempotency key after renewed authorization reconciles through durable receipt. No network inside Reporting SQL transaction.

Private POST `/internal/v1/reporting/definitions` takes strict operation `{kind,id?,version?,after?,limit?,key?,expectedRevision?,body?}`. Kind create/update/archive/get/list/version. Cookies/Origin/X-Tenant-Id rejected on private transport; only signed assertion establishes context. Service URL fixed operator config, loopback HTTP for local; HTTPS for remote. No client URL/credentials accepted. Every endpoint no-store, sanitized errors/correlation, body bound96KiB. Binding source fields and original principals are never trusted from report JSON.

UTC DATETIME(6), no implicit tenant defaults, decimal revision API strings. Remote Identity principal is logical reference, no FK/SQL into another schema. Incomplete draft fields are JSON metadata, never authorization columns.

## Transaction, migration and recovery

Mutation order: authenticate→validate envelope→local transaction→lock deterministic/new or existing definition→current own/all check→receipt replay/hash check→CAS→catalog/version/head update→audit/outbox/receipt→check assertion expiry→commit. No shared UoW, cross-schema query, FK or credentials. Duplicate create serializes on deterministic report ID; subsequent commands lock report before receipt. Request hash binds kind/id/body/expected revision. Conflict/rejected command rolls back all effects. Deadlock/lock timeout surfaces retryable503, retry same command ID; no best-effort partial writes.

Forward migration001 only, per-step SHA256 journal + MySQL named lock. DDL auto-commit crash gap fails closed (existing table without journal requires inspection), never DROP/reset. Operator script restricts development localhost:13306 and exact two Reporting database names, backups preexisting DB and fingerprints old columns/rows before applying, rerun0 required. Runtime granted per table as above, denied journal/DDL/other schemas and immutable UPDATE/DELETE. No migrations edited after first use; later fixes use forward migration.

Rollback: disable BFF route config/service; preserve drafts/history/journal. Definitions pinned by catalog hash survive later kernel versions; storage GET does not reinterpret old JSON. Restore from own DB backup; cross-service identity changes may deny restored owner until reconciled, no automatic ownership reassignment. No deletion/retention daemon or warehouse/projection introduced.
