## Process and lifecycle

One current consultation process per business tenant. Immutable numbered versions contain 1–20 ordered stages and 1–12 ordered behavioral milestone definitions (key, label). Keys are unique lowercase ASCII identifiers; reserved sales/legal keys won, lost, revenue, consent are rejected. These definitions describe agent-attested behavior, never authoritative Deal outcomes or legal consent. Stage transitions may move forward/backward/skip, require reason, and never create milestones.

Version 1 defaults to stages received / consulting / next_step and milestones need_confirmed / next_step_agreed. It is materialized transactionally on first use. Publish with configure capability plus schema.update/all, native CSRF, idempotency and head CAS. Publish changes only subsequently opened sessions. Every new inbox session pins the current version and initial stage in the same Chat transaction. Referral on an active session never resets progress. Close and stage writes serialize on Conversation lock; closed sessions reject stage/need changes. Session version and progress version are separate CAS domains.

Preexisting sessions have no progress (coverage none). Explicit enrollment of an active old session creates partial coverage from now, without backfill. Closed historical sessions cannot be enrolled. For a fully covered new session, late milestone evidence/correction is allowed after close and must have occurred during the session (opening_occurred_at through closed_at); no reopening. Evidence recorded later is excluded from an earlier as_of.

## Need, evidence, correction

A need is an immutable UUID + agent-entered short label scoped to exactly one session. It represents the behavior subject, independent of optional CRM Lead creation. Different needs are never combined. It is not automatically merged when Leads merge and never implicitly joins unrelated Lead/Deal lineage. Agent chooses an explicit need when recording evidence. Labels/reasons must contain no sensitive transcript or patient details.

Manual attestation requires milestone key from the pinned process, occurred_at and a short evidence reason. Optional message_id must refer to a customer inbound message assigned to this exact session; no arbitrary event/Deal/record reference. The agent must have live Conversation read/update, Contact read, and Conversation contact/channel/attribution fields; message evidence additionally requires text field read. All read paths use the same conservative field checks. Server writes actor and recorded_at. Evidence is an agent confirmation, not automated qualification or inferred customer consent.

Facts are append-only: record creates evidence; retract references an existing effective record/replace fact and requires reason; replace references it and supplies replacement evidence for the same need and milestone. Unique supersedes prevents two corrections of the same fact. Correcting a correction targets the current effective replacement. Commands serialize on Conversation and progress, require If-Match and stable idempotency. Retry rechecks live rights before returning its receipt. No physical deletion or invented historical stage transition.

## Native API and UX

GET/POST /api/v1/session-process reads current/version-selected config or publishes immutable next version. GET /api/v1/conversations/{conversation}/sessions/{session}/progress returns pinned config, progress, needs and bounded paginated transition/evidence history. POST same path accepts action enroll, stage, need, record, replace or retract. All writes require native session/CSRF/Idempotency-Key; process publish requires head If-Match, progress writes require progress If-Match (enroll uses 0). Strict JSON and bounded strings/arrays; unknown fields reject.

GET /api/v1/session-funnel accepts from/to opening cohort, process_version, as_of (default server current UTC). to is exclusive; max 93 days. It calls a Chat-owned producer in the current monolith and a pure Reporting reducer; Reporting receives no database credentials. Each cohort session rechecks current record/Contact/field ACL. Return only authorized aggregates with full/partial/none coverage, covered denominator, immutable process version, same-need ordered step counts, rates and UTC bounds/as_of. No current stage-as-conversion, no touch/message joins, no revenue or mock data. Cap scan at 2000 sessions and facts at 20000; reject oversized requests with QUERY_TOO_LARGE, never silently truncate. as_of cannot be future; recorded_at and occurred_at must both be <= as_of. Old as_of reproduces facts under current ACL, not historical access rights.

Funnel cohort uses opened_at in [from,to), recorded before as_of. Full coverage of selected process version is the denominator; partial/none/other-version counts are disclosed separately. For each need, sort effective facts by occurred_at and find an ordered nondecreasing-time sequence of configured milestones. Each session counts once at each completed prefix, choosing any single need that completed that prefix. Different needs cannot combine into a prefix. Equal timestamps are allowed; repeated evidence never multiplies a session. Rates use covered sessions and previous-step count (null for zero denominator). Correction validity uses recorded-time cutoff before filtering occurred_at, so a replacement beyond a cutoff invalidates the old fact rather than resurrecting it.

Inbox Customer360 shows pinned stage, explicit need selector, record/replace/retract actions and history. A process editor and connected session funnel are accessible from that panel, including mobile. Old session history can open its own read/evidence view; process configuration cannot change existing pins. UI explains coverage and manual evidence, errors and stale CAS.

## Acceptance

SP-01 immutable pin/new publish/new session; old session partial enrollment; stage never fabricates fact. SP-02 referral retains stage; close/reopen new pin; serialized close/stage races. SP-03 two needs cannot make one complete funnel; duplicates/touches never inflate. SP-04 corrections, chained replacements, late recording and historical as_of. SP-05 tenant/record/field deny, forged message, reserved outcome key, stale CAS, revoked replay. SP-06 native UI config/stage/evidence/correction/funnel desktop/mobile; historical coverage explicit. SP-07 forward-only migration repeat and full preexisting row preservation. Deal and revenue invariants remain covered by SRC-068; this feature never writes Sales outcomes.

Snapshot consistency refinement: cohort creation, close and progress mutations acquire the tenant process-head lock before stamping recorded times; funnel takes the same lock at READ COMMITTED through completion. Head.updated_at is a durable millisecond watermark advanced to max(DB UTC, previous + 1ms) for each writer/snapshot. Session opened_at/closed_at and progress/evidence recorded_at use that clock; occurred_at stays the supplied event time. A report's as_of is the committed watermark, so later events cannot be backdated into it, even if DB wall time regresses. Explicit as_of beyond the current watermark rejects. Queries also advance the technical watermark; this does not publish a process version. Serialized bounded queries trade write latency for consistency; extraction needs an equivalent committed watermark. Current actor/contact/field ACL remains authoritative on every read. Retraction does not revalidate the parent's historical occurred_at against today's clock; replacement evidence still does.
