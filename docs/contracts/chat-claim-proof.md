# Stable Chat claim proof wire — PLAN-007C11 / SRC-106

Ready scoped contract, 2026-10-18 / CHG-20261018-21. [Dispatch v1](chat-dispatch-v1.md), [Chat claim ledger](../data/chat-dispatch-claim.md), [native Identity](../data/identity-dispatch-ledger.md), [TLS boundary](workload-tls-boundary.md). Source discrepancy: current internal readProof returns full binding/grant/resource snapshot, while DispatchReply claimed contains only claim_id. Do not reinterpret the old minimized receipt as a stable authorization proof.

Add POST `/internal/v1/dispatch/chat-claim-proof`, caller identity or connector → Chat only. Body `ChatClaimProofRead`: schema_version1, operation=chat-claim-proof, request_id UUID, exact DispatchBinding and claim_id UUID. Reply `ChatClaimProofReply`: schema_version1, request_id echo, receipt_id=claim_id, state=claimed, full immutable binding, grant_id, claim_id, resource_context. Strict object/no unknown fields, same16KiB/2s/current workload+business tenant admission rules. No sessions, keys, message text, provider data or send capability. Failed shape/correlation/claim/grant/binding/context is rejected before native Identity consume. This owner observation never reauthorizes a Human by itself.

Compatibility: new dedicated request/reply definitions and route, preserving existing seven DispatchRequest/DispatchReply operations and shapes. Top-level DispatchProtocol accepts the two additive shapes; old clients use old endpoints unchanged and must not be directed to new proof route. Existing receipt-read allowlist remains unchanged; Identity uses the new dedicated proof route, not an undocumented generic receipt-read extension. Existing internal readProof remains for local compatibility.

`NativeChatClaims.readProofWire` validates/copies input, delegates to own immutable stored claim/current-tenant read, then wraps a correlated wire reply. Stable proof remains valid after owner takeover/close or issue expiry; current workload/tenant checks still apply. There is no new transaction effect/table. `wireChatClaimInspector(send)` is an Identity application adapter from validated Consume to new request, requiring strict owner reply schema plus matching request_id/receipt/claim/grant/full binding/context revisions; returns only original StableChatClaim fields. It must be composed with an authenticated expected-Chat transport. Existing ledger still compares full admitted context and current native session/permissions in its transaction.

Acceptance CPW-01: generated strict JSON Schema/TypeScript/OpenAPI with old shapes unchanged. CPW-02: native stored proof round trip and Identity consume via wire adapter; wrong peer/tenant/input denies. CPW-03: malformed/extra fields, wrong correlation/binding/grant/claim/owner/revisions deny; transport rejection propagates, no invented proof. CPW-04: generated drift/strict schema/backend builds and native dispatch regression. No endpoint registration/remote registry bootstrap/main activation in this slice; TLS probe and business adapters remain distinct.

Dependency review: dispatch-claim.ts adds only type:ChatClaimProofRead and type:ChatClaimProofReply from existing @agentic-crm/contracts import. These are owner wire types required by this contract, not foreign domain implementation. Reviewed baseline update keeps268edges and adds these two symbols; no new shared UoW/SQL/runtime edge.
