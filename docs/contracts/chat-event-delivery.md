# Chat durable event delivery — T06

CHG-20261023-20, C2 Ready technical refinement, Codex 2026-10-23. Implements existing [owner event contract](chat-owner-v1.md) and [subscription matrix](../architecture/chat-owner-consumers.md) within [ADR-029 scope](../governance/service-delivery-scope.md). No wire/schema change or migration. Runtime acceptance pending.

Chat mutations insert immutable outbox plus per-subscription deliveries in the same owning transaction. Each stream fixes the registration digest and allocates contiguous sequence under its row lock. Existing registry/control deliveries retain their current digest/envelope. Streams without registered subscribers retain their source event without inventing a recipient or claiming business delivery. Existing pending source events are reconciled into deliveries by an explicit bounded catch-up path before cutover; new producers fan out atomically. Existing delivery identity/sequence is reused.

Relay runs only for an explicit business-tenant allowlist and exact subscription→owner registration. It leases only the first unacknowledged sequence per stream, with UUID fencing and database-time 30-second lease; commits before network I/O. Retries query event-status before event-deliver, using the same immutable identity. Only validated applied/duplicate/reconciled receipt for the same producer/event/consumer/digest with watermark covering the delivered sequence advances ACK. Pending/timeout/404 never advances ACK. Failed attempts back off and quarantine after ten attempts; missing downstream endpoint retains backlog. An expired lease is recoverable; a stale worker cannot ACK or overwrite the newer lease. No payload/credential logging.

Authenticated event-read/replay check that the caller owns the registered subscription and tenant. Read checks every notice binding; replay returns bounded ordered notices and source high watermark without granting business authorization. Administrative retry is an operator action on the same delivery identity, not a new event or automatic purge.

Six Chat notification consumers validate the existing strict event schema and semantic bindings, confirm immutable source delivery, and atomically persist inbox/dedup and applied state. They never repeat the already-committed read-marker/snooze/tag/catalog mutation. Conflicting digest/sequence quarantines; gaps remain pending. The two existing CRM/Workflow activity consumers retain their source-binding/effect semantics. Local notification delivery uses the same durable receipt rules without requiring another service deployment.

Activity inbox recovery uses the existing inbox lease/attempt columns, an explicit tenant allowlist and a bounded round-robin scanner. It claims only the earliest unresolved event of each stream, queries producer replay/read for missing predecessors (at most100 per page), validates notice/digest/tenant/sequence, and applies through the same source-binding consumer. Network calls occur outside SQL transactions. The lease is checked again inside both staging and final effect transactions; an expired worker cannot apply effects or release another worker's lease. Source outage retains pending state with backoff; ten unsuccessful attempts quarantine without purging identity. Local and Activity consumers share one authenticated route map. Relay also rotates tenants between claims.

Legacy catch-up is an explicit operator call against Chat storage, requiring the exact frozen writer epoch under a gate lock. Active/stale epochs fail closed. It stages at most100 source rows in original creation order, reuses persisted delivery sequences, and rejects any missing historical event whose stream already contains a newer source event. It never renumbers delivered history; such discrepancies require export reconciliation before cutover. Runtime startup does not invoke catch-up.

Validation required: actual retained MySQL rollback/atomicity and concurrent stream allocation, native HTTP read/replay/delivery/status, wrong-tenant/subscriber denial, same-key conflict, gap, lost ACK, lease expiration/stale worker, restart, retry/quarantine, unavailable remote consumer and local effect non-repetition. Test receiver is explicitly synthetic and uses its own fixture deliveries; no real subscription is falsely ACKed. Required composed runtime/cutover remain later gates.
