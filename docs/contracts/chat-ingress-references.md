A mapping reservation also checks the Contact gate; it cannot enter while that Contact is closing. Cancelled barrier IDs cannot be reused to close again. ## Scoped connection status writer — CHG-20261022-02

Ready local Channels operator port closes the existing connection reference barrier before setting channel_connection.status=disabled. It is not a new public administration UI. It processes at most100 held admissions per invocation, asks Chat for authenticated terminal proof outside SQL, then locks the same gate and checks no holds before changing status and inserting a minimized audit atomically. Outage/unknown keeps status unchanged and gate closing; retry uses the same barrier after restart. A commit that won before close remains committed; no message/unknown delivery is rewritten or resent. Repeating completed disable has no additional audit/effect.

Explicit re-enable requires the matching completed disable barrier, locks the gate and connection, changes status to active and opens the gate in the same local transaction. The previous barrier ID remains recorded so a delayed disable retry cannot close an already re-enabled connection. Wrong barrier/tenant fails. Rebind and credential changes remain unsupported. Reference-runtime credentials keep connection SELECT only; the trusted status operator receives UPDATE(status), owning-ledger DML and audit INSERT. No foreign SQL or schema change.

This closes the Channels ingress reference/status race. D2 Connector attempt admission and its separate connector_connection remain governed by the dispatch contract; composition must also fence that transport before claiming a global connection shutdown. Completing this local port alone does not establish the broader T09 single-writer cutover.
