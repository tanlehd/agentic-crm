## API and lifecycle v1

Native routes: POST /api/v1/reporting/runs with {definition,generation?} and Idempotency-Key UUID creates queued run. GET /:id returns status metadata, POST /:id/execute with {} executes/resumes, POST /:id/cancel with {} cancels, GET /:id/result?format=json|csv returns completed aggregate. POST requests require session/Origin/CSRF; GET requires native session. X-Tenant-Id is selection, not authority. Same explicit report_definition run/all and report_mock_source read/all as preview; CSV additionally export/all. Every operation also requires exact owner principal match, even if caller has all run grants; another tenant/owner sees404. No default grants or implicit owner transfer.

Private POST /internal/v1/reporting/runs accepts strict operation: create {kind,key,request:{definition,generation?}}, or {kind:get|execute|cancel|result,id,format?}; format allowed only for result. Signed admission audience reporting-run-v1, same fields/lifetime5s as query. Verify raw body and audience, reject cookies/Origin/tenant headers/query strings. Live Identity revision/grants and native session rechecked before public delivery. Admission rechecked after row lock and before each commit. Post-admission cancellation/creation may commit before a later public revocation denial, as with draft commands; create-key or status lookup reconciles after reauthorization. No network inside SQL transaction.

Create validates semantic definition against ready snapshot and pins immutable binding/generation/catalog implicitly via the generation plus executor_version=mock-query-v1. Existing key returns the same run/current status without changing snapshot even after active generation changes. Different request for that tenant/principal/key=409 IDEMPOTENCY_CONFLICT. No authority token or auth scope stored in run. Every execute/get/result/cancel requires fresh admission. Preview endpoint remains read-only and compatible.

States queued→running→completed|failed; queued/running→cancelled. Running lease15s, attempt fence increments for each claim; another execute while lease valid=409 RUN_BUSY. After process interruption and lease expiry, explicit execute with fresh owner authorization reclaims the same pinned generation. Only matching current attempt may finish, before lease expiry; stale/late completions=409 RUN_FENCE_LOST. Cancel is immediate authoritative state change, invalidates result publication even if computation cannot be interrupted. Completed/failed/cancelled are immutable terminal states; repeat cancel of cancelled and execute of completed/failed/cancelled return current metadata. Cancel of other terminal state=409 RUN_TERMINAL. Failure stores only sanitized code; retry terminal failure requires a new key/run. Unknown executor version denies execution, never silently upgrades semantics.

Execution happens outside SQL transactions using the existing bounded query service. Query errors or dependency failures can commit failed(code); admission expiry or lost response may leave running for later lease recovery. No automatic worker, scheduler or unawaited background Promise. API execute is bounded by existing4.5s BFF timeout/5s admission; run persistence does not extend authorization lifetime. Completion stores JSON aggregate<=2MiB; execute/status return metadata only. Result reads current permission and owner checks before retrieving aggregate; CSV is rendered anew with export grant. Query concurrency limit remains per instance; DB leases serialize attempts across instances for the same run.

Metadata: id,owner_principal_id,binding_id,generation_id,executor_version,state,version(decimal string),attempt,error_code|null,created_at,updated_at,expires_at. No definition/raw rows/result in status. Logical lifetime24h from creation (410 RUN_EXPIRED for owner after current auth); physical synthetic rows/events retained, no automatic purge or key reuse. Long-term retention/purge/worker throughput is not a production feature claim. No saved-report publication/drilldown semantics inferred from run completion.
